## 1. S2 データソース詳細

### 1.1 目的・主要操作

- 1 つのデータソースの設定値・ロック状態・直近のジョブ・インデックス件数を確認し(AF-2、AF-15、AF-8)、クロールを起動し(AF-3)、編集・削除に進み(AF-1、AF-16)、止まったロックを解放する(AF-7)。
- 主操作は「クロール起動」(primary)。「編集」は outlined、「その他の操作」(`⋮`)に「削除…」。
- テンプレート: 詳細(`detail`。DS 6.2)。route: `/sources/:sourceId`。`meta.parent` = データソース(S1)。ナビの現在地は「データソース」。

### 1.5 ロック状態カード(AF-7。導出。ゲート C 承認済み。取得経路は Admin API 設計)

カード見出しは「ロック状態」。ロックの有無・保持ジョブの状態・リース期限から次の 6 種を出し分ける(モック `#s2-lock`)。ボタンの色は確認ダイアログの中だけ warning にする(ページ上では outlined)。

| 状態 | 見せ方 | 操作 | 根拠 |
| --- | --- | --- | --- |
| ロックなし | チェック+「ロックはありません。クロールを起動できます。」 | なし | |
| 実行中のジョブが保持(リース期限内) | 「実行中」タグ+「ジョブが実行中です」+ジョブ ID・リース期限。案内「実行中のジョブのロックは解放できません。止めるには、ジョブ詳細で「取消」を使います」 | 「ジョブを表示」(J2) | crawler-api 4.3(リース期限内は解放不可。取消を使う) |
| リース切れのジョブが保持 | warning アラート(`role="status"`)「止まったジョブのロックが残っています」+ジョブ ID・リース期限。「クロールの起動は「ロック保持中」で拒否されます」 | 「ロックを解放…」(DLG-5)、「ジョブを表示」 | AF-7。ジョブ詳細(J2)にも同じ操作 |
| 孤児ロック(ジョブ記録がない、またはジョブが終了済み) | warning アラート「動いているジョブのないロックが残っています(孤児ロック)」+「対応するジョブ記録がない、またはジョブが終了済みです」。小さく「承認済み(ゲート C): 孤児ロックの解放の入口をこの画面に置く」 | 「ロックを解放…」(DLG-5 孤児版) | AF-7。入口の記載が機能設計書になく、S2 に置く(承認済み(ゲート C。#1)) |
| 削除ジョブが保持(リース期限内) | 「削除中」タグ+「削除ジョブがロックを保持しています」+ジョブ ID・リース期限。案内「リース期限内は解放できません。完了を待ってください」 | なし | crawler-api 4.3 |
| ロック取得の直後(受付の途中の可能性) | 時計アイコン+「ロックを取得した直後です」。案内「受付の途中の可能性があるため、解放できません。しばらくしてから再読み込みしてください」 | 「再読み込み」 | crawler-api 4.3(取得直後は解放しない) |

- 解放しても、ジョブは再起動されない。解放後は「クロール起動」(DLG-1)で起動し直す(AF-7)。
- 解放の確認ダイアログ(DLG-5)の孤児版: 見出し「ロックを解放しますか」。警告枠「解放すると次のようになります」+「ロックだけが消えます。対応するジョブはないため、ジョブの状態は変わりません」「ジョブは起動されません。解放後にクロールを起動してください」。確認チェック「ジョブが動いていないことを確認しました」(チェックするまで実行ボタンは無効。理由「確認にチェックすると解放できます」)。帯と実行ボタンは warning(水準は要確認・警告つき)。モック `#dlg-unlock-orphan`。リース切れジョブ版は `jobs-v0.1.md` の DLG-5。
- 解放できなかった場合(409 `lock_in_use`)は、ダイアログを開いたまま内側に消えないアラートで理由と次の行動を示す: リース期限内の実行中・実行待ち → 「ジョブが実行中です。ジョブ詳細で取消を使ってください」/ リース期限内のソース削除 → 「削除ジョブが実行中です。完了を待ってください」/ 取得直後 → 「ロックを取得した直後です。しばらくしてからやり直してください」。
- 解放後はカードを再取得し、ロックなしの表示に変える。成功のスナックバー「ロックを解放しました」。

### 1.6 直近のジョブカード(AF-8)

項目: ジョブ ID(等幅・J2 へのリンク)、状態(タグ。DS 4.1)、起動(手動 / 定期)、**起動時の指定**(「強制削除モード: なし / 再書き込みモード: なし」。ジョブ記録の受付時の指定。表示は導出。ゲート C 承認済み。機能設計書 AF-8)、開始 / 終了。カード末尾に「このデータソースのジョブをすべて表示」(J1 をデータソースで絞り込んだ URL へ)。失敗のジョブでは、失敗の理由を 1 行で添える(理由の日本語表記は `jobs-v0.1.md` の表)。

- 直近のジョブがない(未実行): カード内に「まだクロールしていません。「クロール起動」で最初のクロールを実行できます。」(モック `#s2-nojob`)。

### 1.7 インデックスカード(AF-15)

登録文書数(「1,284 件」)と、補足「数え方(抽出失敗の文書を含むか)は Admin API 設計で確定」(AF-U-6。実装時にこの補足は仕様確定後に削除または具体化する)。カード末尾に「スキップ・抽出失敗などを確認する(文書の確認)」(X1 へ)。取得できないときは「—」+「取得できません」。

### 1.10 インタラクション・レスポンシブ・アクセシビリティ

- 更新: 画面を開いたときと、操作(起動・解放・取消の受付など)の後に再取得する。手動の「更新」は置かない(戻る・再読み込みで足りる。承認済み(ゲート C。#33))。自動更新はしない。
- レスポンシブ: DS 7 章。1145px 以上 2 列、840〜1144px は 1 列(サイドバーは常時表示)、840px 未満は上部バー+ドロワー、キー・バリューは 600px 未満で 1 列に積む。操作ボタンは折り返す。375px・320px で崩れない(確認済み)。
- a11y: `h1` は識別子。パンくずは `nav aria-label="パンくず"`。各カードは `aria-labelledby`(見出し)。ロック状態の警告は `role="status"`(読み込み後に表示される情報。緊急ではない)、取得失敗・エラーは `role="alert"`。状態は色・形・文言で示す(DS 4.1)。値のない項目は「—」+読み上げ用の「未設定」「なし」。
- `data-testid`(DS 9 章): `s2-lock-card`、`s2-state-loading` / `s2-state-error` / `s2-state-notfound` / `s2-state-stale`、`dlg-source-delete`、`dlg-crawl-start`、`dlg-lock-release`。ボタンはロールとラベルで特定する。

## 2. S3 データソース登録・S4 データソース編集(AF-1)

### 2.1 目的・主要操作

- S3: データソースを登録する。S4: 登録済みデータソースの設定を更新する(全置換。現在値の表示が前提)。どちらも主操作は「登録」「保存」(primary)。キャンセルは text。
- テンプレート: フォーム(`form`。DS 6.3)。route: `/sources/new`、`/sources/:sourceId/edit`。パンくず: S3 は「データソース › 登録」、S4 は「データソース › {識別子} › 編集」。
- 登録・更新は Crawler への中継(Admin API 経由)。保存時に接続の確認はしない(`CAPI-P-8`)。

### 2.2 レイアウト(幅 1280px。モック `#s3-normal`・`#s4-normal`)

```text
データソースを編集 demo-handbook
┌ (S4 のみ)情報アラート: 保存した設定は、次に開始するジョブから使われます … ┐
┌ 基本 ─────────────────────┐   カードは 1 列、最大幅 720px
│ 識別子(source_id)必須 [          ]   │   (入力欄の本体は幅いっぱい、単位付きは最大 280px)
│ 種別 必須            [ローカル… ▾]    │
├ 取得設定 ────────────────────┤
│ 取得元のパス 必須     [/mnt/…       ]  │
├ 実行周期 ────────────────────┤
│ cron 式              [0 3 * * *   ]  │
│  空にすると手動のみ。… Asia/Tokyo で解釈 │
├ 削除の判断 ───────────────────┤
│ TTL 必須   [ 30 ] 日                  │
│ 削除の割合しきい値 必須 [ 20 ] %        │
│ 最小件数 必須 [ 10 ] 件                 │
└──────────────────────────┘
                          [キャンセル] [保存]
```

- カードは 4 つ(基本 / 取得設定 / 実行周期 / 削除の判断)。1 本のフォームとして 1 つの `<form>`、各カードは `aria-labelledby`。保存ボタンはフォーム末尾の右。

### 2.3 項目

| 項目 | 部品 | S3 | S4 | ヘルプ(入力欄の下・12px) | 画面の検証(エラー文) |
| --- | --- | --- | --- | --- | --- |
| 識別子(`source_id`) | テキスト(等幅)。`autocomplete="off"` | 必須・空欄・例「demo-handbook」 | 読み取り専用(破線の枠) | 「半角英数字で始まり、半角英数字と . _ - が使えます(256 文字まで)。登録後は変更できません。」 | 形式 `[A-Za-z0-9][A-Za-z0-9._-]*`・256 文字以内。「半角英数字で始まり、半角英数字と . _ - だけで入力してください」。既に登録済みなら「この識別子は既に登録されています。別の識別子を入力してください」(409 `source_already_exists` を項目へ) |
| 種別(`connector_type`) | セレクト | 必須。MVP は 1 選択肢(「ローカルディレクトリ / ファイル共有」) | 読み取り専用 | 「登録後は変更できません。」 | — |
| 取得元のパス(`connector_config`) | テキスト(等幅) | 必須・空欄・例 | 現在値 | 「Crawler のコンテナから見たパス。保存時に接続の確認はしません。接続できない場合は、クロールを起動したときにジョブが失敗します。」 | 空: 「取得元のパスを入力してください」。形式違反は Crawler の項目別エラーを表示(`connector_config`。Connector 設計が定める) |
| 実行周期(`schedule_cron`) | テキスト(等幅) | 任意・空欄・例「0 3 * * *」 | 現在値(null は空) | 「分 時 日 月 曜日の 5 項目を空白 1 つで区切ります(例: 0 3 * * * は毎日 3:00)。空にすると手動のみで実行します。この cron は **Asia/Tokyo**(Crawler の設定)で解釈されます。」 | 「5 項目の cron 式で入力してください(例: 0 3 * * *)」(Crawler の検証。細部は `CAPI-P-30`。ユーザー未確認) |
| TTL(`ttl`) | 数値(テキスト+`inputmode="numeric"`)+付属「日」 | 必須・空欄・例「30」 | 現在値(日。割り切れなければ秒の表示に切替) | 「最後に見つかった日時(存在確認日時)からこの日数を過ぎた文書が、削除の対象になります。1 以上の整数。」 | 「1 以上の整数で入力してください」。9 桁まで |
| 削除の割合しきい値(`ratio_threshold`) | 数値(`inputmode="decimal"`)+付属「%」 | 必須・空欄・例「20」 | 現在値(%) | 「削除対象が、削除前の登録文書数のこの割合を超えると、そのクロールでは削除しません。0 以上 100 未満。」 | 「0 以上 100 未満で入力してください」(Admin API が最終検証。範囲外は Crawler に渡さない。`CAPI-K-3`) |
| 最小件数(`min_delete_count`) | 数値+付属「件」 | 必須・空欄・例「10」 | 現在値 | 「削除対象がこの件数以下なら、割合に関わらず削除します。0 以上の整数。」 | 「0 以上の整数で入力してください」。9 桁まで |

- ラベルの横に「必須」(DS 4.6)。必須の項目を空のまま送信すると「…を入力してください」。
- **入力単位と変換(AF-U-7。承認済み(ゲート C。#2))**: 画面の入力は TTL=日、しきい値=%、最小件数=件。保存時に Admin API が TTL を秒(×86,400)、しきい値を割合(÷100)に変換する(crawler-api の値は秒・0〜1。変換は Admin API の領域。`CAPI-U-3`)。表示は逆変換。小数は、しきい値のみ小数第 2 位まで許可する(例: 12.5)。
- **既定値(AF-U-7。承認済み(ゲート C。#2))**: 補わない。必須項目は空欄で始め、例は「例: 30」のようにプレースホルダーで示す。理由: 削除の判断に関わる値で、既定値を決めていない(`CAPI-P-7`、Indexer 設計の未決 U-1)ため、意図した入力を求める。
- **`ttl`・`min_delete_count` の検証(AF-U-7。承認済み(ゲート C。#3))**: Crawler は整数であることしか検証せず、範囲を見ない(`CA-K-16`)。画面で範囲(上表)を検証し、Admin API でも同じ検証を行う前提で Admin API 設計に申し送る。上限は設けない(int64 の範囲外は考えない。ユーザー判断 2026-11-16)ため、桁数(9 桁)だけ入力で制限する。
- AF-U-5 は文書単位ビュー(X1)の未決で、G1 に該当する部分はない(次回の G3 で扱う)。

### 2.4 検証とエラー表示(DS 4.6)

- タイミング: 項目からフォーカスが外れたときに、その項目を検証して項目の下に出す。送信時に全項目を検証し、エラーがあれば送信せず、フォーム上部に件数付きのエラー要約(`role="alert"`、各項目へのリンク)を出し、フォーカスを要約に移す。
- サーバー(Crawler・Admin API)の項目別エラー(`details.errors` の `field`・`reason`)は、同じ形で項目の下に出す。`reason` と文言の対応(承認済み(ゲート C)。`reason` の値そのものは Crawler 設計の案):

| `reason` | 画面の文言 |
| --- | --- |
| `required` | 「…を入力してください」 |
| `format` | 項目ごとの形式の文言(上表) |
| `type` | 「…の形式が正しくありません」 |
| `unsupported`(種別) | 「この種別は選択できません」 |
| `unknown_field` / `read_only` | 画面は送らない項目のため通常は出ない。出た場合はフォーム上部のアラートに「想定外の応答です」+詳細 |
| 409 `source_already_exists` | 識別子の項目に「この識別子は既に登録されています…」。**`status=deleting` のデータソースの識別子でも同じ 409 が返る**(設定がまだ残っているため。crawler-api §4.4.1)。応答から削除中と分かる場合は、補足「削除中のデータソースと同じ識別子です。削除が完了してから登録してください」を添える(分からない場合は同じ文言のまま)(案) |
| 409(`status=deleting`。S4) | S4 全体を編集不可にする(2.6) |

- 通信エラー・サーバーエラー(5xx): 入力内容は残し、フォーム上部に消えないアラート「設定を保存できませんでした。Crawler に接続できません。入力内容はそのままです。時間をおいて、もう一度保存してください」(スナックバーは使わない。モック `#s4-submit-error`)。
- タイムゾーンを取得できないとき(AF-U-13。承認済み(ゲート C。#6)): cron のヘルプの最後に、警告アイコン付きの文「適用されるタイムゾーンを取得できません。Crawler の設定を確認してください。意図した時刻とずれる可能性があります。」(warning の文字色・600)。入力と保存は止めない(モック `#s4-tz`)。次回実行予定日時は表示しない(機能設計書 AF-U-13。MVP に含めない)。

### 2.5 保存の挙動

- 送信中: ボタンを無効にし、ボタン内に進行表示+「登録中…」(S4 は「保存中…」)。理由の文「登録しています。完了すると詳細画面に移動します。」(`role="status"`)。入力欄は変更できるままにする(失敗時に直せる)。二重送信を防ぐ。
- 成功: S3 は S2 へ移動し、スナックバー「データソースを登録しました」(+「クロール起動」への導線は置かない)。S4 は S2 へ移動し、スナックバー「設定を保存しました」。移動後に S2 のデータを再取得する。
- 反映の注意(S4。AF-1): フォーム上部に情報アラート(`role="note"`)「保存した設定は、次に開始するジョブから使われます。実行中のジョブには反映されません(実行待ちのジョブには、開始時に反映されます)。」
- キャンセル: 保存せずに S1(S3)または S2(S4)へ戻る。未保存の変更の離脱確認は置かない(要件にない。MVP)。

### 2.7 インタラクション・レスポンシブ・アクセシビリティ

- 項目の並びは上から下。Tab 順は、(パンくず → )アラート → 基本 → 取得設定 → 実行周期 → 削除の判断 → キャンセル → 保存。読み取り専用の項目もフォーカスできる(値を読み上げるため)。
- すべての入力に `<label>`。ヘルプ・エラーは `aria-describedby`。エラーのある項目は `aria-invalid="true"`。
- レスポンシブ: フォームは最大幅 720px。幅 600px 未満は入力欄の高さ 44px。単位付きの入力は最大 280px、狭い幅では幅いっぱい。ボタンは折り返す。
- `data-testid`: `s3-form` / `s4-form`、`s3-error-summary`、`s4-state-deleting`。入力はラベルで特定する。
