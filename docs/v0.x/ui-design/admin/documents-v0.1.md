## 1. 目的・主要操作

- 利用者(管理者)が、データソースごとに、確認が必要な文書(スキップ・抽出失敗・原本サイズ超過・要約未生成)を一覧し、原因を調べる(AF-11〜14)。同じ画面で、そのデータソースの登録文書数を確認する(AF-15)。
- 主操作はなし(読み取り専用の一覧)。副次の導線は「データソースの詳細(クロールの起動)」(S2 へ。原因を解消したら、そこでクロールを起動する)。
- テンプレート: 一覧(`list`)+タブ(`VTabs`)。route: `/documents`。クエリ: `source`(データソースの識別子)、`tab`(`skipped` / `extract-failed` / `oversize` / `summary-pending`。既定 `skipped`)、`page`、`size`、`sort`。ナビの現在地は「文書の確認」。
- route `meta`: `../admin-view-v0.1.md` 4.2 の表のとおり(`title: '文書の確認'`、`template: 'list'`、`nav: { label: '文書の確認', icon: mdiFileSearchOutline, group: 'inspect', order: 0 }`)。値は 4.2 を正とし、本書では繰り返さない。

## 5. タブと拡張点(承認済み(ゲート C。#16)。AF-29 の拡張)

タブの定義を 1 つの表(配列 `documentTabs`)にまとめる。タブの追加(AF-29「すべての文書」など)は、この表に 1 行足し、列と取得元を定義するだけで済む。

| `id` | ラベル | AF | 取得元(Admin API が読む) | 既定の並び | 件数の取得 |
| --- | --- | --- | --- | --- | --- |
| `skipped` | スキップ | AF-11 | スキップ記録(`loreley-jobs`。CA 3.3.3) | 直近のスキップが新しい順 | 一覧の総件数 |
| `extract-failed` | 抽出失敗 | AF-12 | 検索インデックス(`index_status=extract_failed`。IA K53) | 存在確認日時の新しい順 | 同上 |
| `oversize` | 原本サイズ超過 | AF-13 | 原本サイズ超過記録(CA 3.3.4) | 直近の検出が新しい順 | 同上 |
| `summary-pending` | 要約未生成 | AF-14 | 検索インデックス(`summary_status=pending`) | 登録日時の新しい順 | 同上 |
| (将来)`all` | すべての文書 | AF-29 | 検索インデックス(`source_id`) | — | — |

- 各定義が持つもの: ラベル、AF、列定義、並べ替え可能な列、注記の文、空状態の文、行の操作(MVP は全タブで「なし」。AF-30 の手動再試行は行の操作として足せる)。
- タブ名の件数は、各タブの一覧の総件数。1 つの要約取得で 4 件を返す設計(1 リクエスト)でも、タブごとに取得する設計でもよい(Admin API 設計)。件数を取得できないタブは「—」(視覚的に隠した「件数を取得できません」)にし、そのタブを開いたときに 8 章のエラー表示にする。
- 行ごとの詳細画面は MVP にない(文書ブラウザ AF-29 の `detail` として将来足す)。そのため行の識別子(`external_id`)はリンクにせず、選択・コピーできる文字として表示する。
- キーボード: タブは `role="tablist"`。左右矢印で移動、Home / End で端へ、選択は矢印移動と同時(自動選択)。Tab キーでタブリストからパネルへ移る。選択状態は `aria-selected`、`aria-controls` でパネルと結ぶ(`VTabs` の挙動は実装後に確認)。

## 6. 各タブの列と表示規則(承認済み(ゲート C。#17))

共通: `external_id`(パス。等幅・13px)は折り返す(`overflow-wrap:anywhere`)。日時は `YYYY-MM-DD HH:mm`(DS 4.9)。**補足行**(文書の下の 12px・補助文字)に、優先度の低い項目を出す。1145px 以上でも補足行を使い、パスを読みやすい幅に保つ。

### 6.1 スキップ(AF-11)

| 列 | 内容 | 表示 | 並べ替え |
| --- | --- | --- | --- |
| 文書 | `external_id`。補足行: 「試行 N 回 · 連続 M 回 · ジョブ ID(J2 へのリンク)」(`attempts`、`consecutive_skips`、`last_job_id`) | 等幅・折り返す | なし |
| 理由 | 日本語の固定文(1 行目)+「取得段階 / 登録段階 · 分類名(等幅)」(2 行目)。`stage`=`fetch`→取得段階、`index`→登録段階 | 記録の `reason` は「分類名: 固定文」の形(CA 3.3.3)。形が違うときは `reason` をそのまま 1 行目に出す | なし |
| 既存・新規 | 「既存」(枠線の warning。補足「古い内容で検索に残る」)/「新規」(枠線。補足「検索に未登録」)/「—」(補足「確認できません」)(7.2。承認済み(ゲート C。#19)) | タグ+補足 | なし |
| 初回 / 直近 | `first_skipped_at`(1 行目)、`last_skipped_at`(2 行目) | 12px | 直近(降順が既定・昇順) |

- 理由の日本語(承認済み(ゲート C。#17)。元の固定文は CA-P-69): `fetch_not_found`=取得時に文書が見つからなかった / `fetch_permission_denied`=取得の権限がなかった / `fetch_transient`=取得の一時的な失敗が続いた / `connector_internal_error`=Connector の想定外の例外 / `document_rejected`=Indexer が文書を拒否した。未知の分類は固定文をそのまま出す(コードの形式が変わっても壊れない)。
- 注記: 「取得または登録に失敗して、スキップした文書です。「既存」の文書は古い内容のまま検索に残っていて、「新規」の文書は検索にまだ登録されていません。この一覧は直近のクロールの結果です。原因を解消して再クロールすると、成功した文書は一覧から消えます。」(SD §3.1・CA 6.4)

### 6.2 抽出失敗(AF-12)

| 列 | 内容 | 並べ替え |
| --- | --- | --- |
| 文書 | `title`(太字。なければ「(タイトルなし)」)+`external_id`(等幅) | なし |
| 形式 | `mime_type`(等幅)。840〜1144px では補足行に移す | なし |
| サイズ | `size`(MB / KB 表記。右揃え) | なし |
| 更新日 | `source_updated_at` | なし |
| 存在確認日時 | `last_seen_at` | 降順が既定 |

- 注記: 「抽出に失敗し、タイトルとメタデータだけを登録した文書です。本文では検索できません。次のクロールで毎回、抽出をやり直します。アクセス権や形式を見直したあと、データソースのクロールを起動して再処理してください。」(PD §4.2、SD)
- スキップ件数には数えない(PD §4.2)。この一覧は検索インデックスの読み取り(形・取得条件は Admin API 設計。IA U-30。AF-U-6)。

### 6.3 原本サイズ超過(AF-13。承認済み(ゲート C。#18))

| 列 | 内容 | 並べ替え |
| --- | --- | --- |
| 文書 | `external_id`。補足行: 「初回 日時 · ジョブ ID」(`first_detected_at`、`last_job_id`) | なし |
| 拒否した側 | 「Crawler」/「Indexer」(枠線のタグ。`detected_by`) | なし |
| 原本のサイズ | 「412.6 MB」+バイト値(等幅・12px)。分からないとき(`size` なし)は「不明」+補足「サイズが分かる場合だけ表示」 | なし |
| 直近の検出 | `last_detected_at` | 降順が既定 |

- 注記: 「原本が上限のサイズを超えているため、取り込まれていない文書です。すでに検索にある同じ文書は、そのまま残っています(書き換えも削除もされません)。上限を超えた原本は、データソースの設定の除外条件で対象から外すか、原本を小さくしてください。本文が上限で切り詰められた文書は、ここには表示されません。」(PD §4.2 の確定事項に基づく。「除外条件」はデータソース設定の説明で、`connector_config` の項目の有無は Connector 設計による。画面は文言として案内するだけ)
- 上限の値は表示しない(設定値の取得経路が決まっていないため)。ジョブの状態には影響しない(CA 6.5)ので、ジョブ側の警告とは連動させない。

### 6.4 要約未生成(AF-14)

| 列 | 内容 | 並べ替え |
| --- | --- | --- |
| 文書 | `title`+`external_id` | なし |
| 形式 | `mime_type`(840〜1144px では補足行) | なし |
| 更新日 | `source_updated_at` | なし |
| 登録日時 | `indexed_at` | 降順が既定 |

- 注記: 「要約がまだ生成されていない文書です。要約は、登録のあとで順に生成されます。生成が進むと、この一覧から減ります。「再書き込みモード」でクロールした直後は、要約が有効なら、抽出に失敗した文書を除く全件がここに並びます。」(AF-14。search-index 2.3)
- 対象は要約が有効で `summary_status=pending` の文書。無効(既定。`disabled`)の文書・抽出失敗の文書は対象にしない。
- 実装・検証の前提(機能設計書 AF-14): 要約機能(LLM プロバイダ)が未実装の間は、要約を有効にすると Indexer が起動しないため、このタブの実データでの検証は要約機能の実装後になる。画面の実装は先に進められる(0 件の空状態として動く)。

## 7. AF-U-5 の扱い(承認済み(ゲート C。#18〜#20))

### 7.1 (a) 原本サイズ超過の表示方法(承認済み(ゲート C。#18))

PD §9.2 #8 が「利用者への表示方法」を未決とするものの画面側の案: **専用タブ+一覧**で表示する(6.3)。理由: PD 4.2 が、スキップ・抽出失敗とは別の「文書単位のエラー」として定義し、スキップ件数にも数えないため。ジョブ詳細(J2)の登録結果の「原本サイズ超過」件数(AF-9)から、このタブへ移動できる。ジョブの状態への影響は Admin API・Crawler 側の決定事項で、画面は影響しない前提で作る。

### 7.2 (b) 「既存/新規」の導出(承認済み(ゲート C。#19)。導出方法は Admin API 設計で未決)

SD §3.1 は「既存文書か新規文書か(既存なら古い内容のまま検索に残る)」を表示項目とするが、記録項目にはなく導出が要る(機能設計書 AF-11)。画面は導出結果の 3 値を表示するだけにする: 既存 / 新規 / 確認できません(「—」)。導出方法(スキップ文書の `document_id` で検索インデックスを引く、など)は Admin API 設計(AF-U-5(b)・AF-U-6)。ページ内の文書(最大 100 件)の一括取得で足りる想定。引けなかった文書は「確認できません」とし、行ごとに失敗してもページ全体は表示する。

### 7.3 (c) 本文の切り詰めの表示先(承認済み(ゲート C。#20))

PD §4.2 は「切り詰めたことを表示する」とするが、表示先が §4.6 の項目にない。**MVP の X1 には置かない**(切り詰めた文書は索引に登録済みで、確認して対応する対象ではないため。「確認が必要な文書」の 4 区分に入らない)。切り詰めの表示は、文書を読む利用者に近い Search View(検索結果・文書表示。別タスク)と、AF-29 文書ブラウザの列(`truncated`)で扱う。X1 の原本サイズ超過タブの注記に「本文が上限で切り詰められた文書は、ここには表示されません」と書いて、混同を防ぐ。

## 9. インタラクション

- 更新: 手動(「更新」ボタン)のみ(承認済み(ゲート C。#17)。自動更新はしない。J1・S1 と同じ)。
- データソース・タブ・ページ・並べ替えの変更は、URL のクエリに反映する(戻る・再読み込み・共有で再現)。タブ移動はスクロール位置を先頭に戻さない(表の上端までは戻す)。
- ホバー: 行は `primary` の 5%。リンク(ジョブ ID)は下線付き。操作要素は DS 2.6 のフォーカスリング。
- 動き: DS 2.6 のとおり(進行バーとスケルトンのみ)。

## 11. アクセシビリティ

- 見出し: `h1`「文書の確認」のみ。カードに `aria-label`。表に `<caption>`(視覚的に隠す。データソースとタブ、並び順を含める)、`<th scope="col">`、並べ替え列に `aria-sort`。
- タブ: `role="tablist"` / `tab` / `tabpanel`、`aria-labelledby`。件数はタブの名前の一部として読み上げる(「スキップ 6」)。件数取得失敗は「件数を取得できません」。
- 「既存」「新規」・理由の分類は文言で伝える(色だけにしない)。
- エラー(データなし)は `role="alert"`、古いデータの警告も `role="alert"`。注記は読み上げ対象の通常のテキスト。
- 本文内のリンク(ジョブ ID、「データソースの詳細」など)の操作領域は高さ 24px 以上(WCAG 2.2 の 2.5.8)。
- データソース変更時の結果の読み上げ: 件数の変更を `role="status"` で通知しない(連続読み上げを避ける。J1 と同じ)。
