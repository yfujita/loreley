## 1. 目的・主要操作

- 利用者(管理者)が、OpenSearch のクラスタが健全か(green / yellow / red)、どんなインデックスがありドキュメントが何件か、シャードがどのノードに配置されているかを確認する(AF-17)。インデックスの一覧とドキュメント件数は、シャード配置のマトリクスの列・列見出しで見る(ユーザー指示 2026-11-22)。インデックスが多いときは、名前・状態で絞り込んで表示する(3.5。**絞り込みフォームの追加はユーザー指示 4 回目で承認済み。条件の種類は案**)。検索が遅い・失敗するといったとき、またダッシュボード(D1)で opensearch の異常を見たときの調査先。
- 主操作はなし(読み取り専用)。操作は「更新」(outlined)と、表示するインデックスの絞り込み(3.5。読み取りのみ。変更操作はない)。
- テンプレート: ダッシュボード(`dashboard`。読み取り専用の概況。DS 6.4)。route: `/opensearch`(クエリ: `q`、`state`。3.5。J1・X1 の流儀)。ナビの現在地は「OpenSearch」。
- route `meta`: `../admin-view-v0.1.md` 4.2 の表のとおり(`title: 'OpenSearch'`、`template: 'dashboard'`、`nav: { label: 'OpenSearch', icon: mdiServer, group: 'inspect', order: 1 }`)。値は 4.2 を正とし、本書では繰り返さない。

### 3.0 概況(クラスタ全体の状態。カードの上部の領域。**クラスタの状態カードをシャード配置に統合することと、統合したカードを「クラスタ状態」と呼ぶことはユーザー指示で承認済み。概況の構成・位置の細部は案(PR レビューで確認)**)

旧「クラスタの状態」カードの情報(クラスタ名・状態タグと説明・件数 4 項目)を、カード「クラスタ状態」の**上部の領域**として残す。

- **構成(上から)**: ① クラスタ名(ラベル 12px `on-surface-variant`+値 等幅)と状態(ラベル+状態タグ(3.1))を横に並べる(幅が足りなければ折り返す。左右 16px・上 12px)。② 状態の説明(3.1 の文。14px・`on-surface-variant`・最大幅 90ch(半角 90 文字相当)。幅 375px では 3〜4 行に折り返す)。③ **件数 4 項目: 「ノード」「アクティブ」(値の右に「うち移動中 n」)「未割り当て」「初期化中」**。項目名に「シャード」を繰り返さない短いラベルにする(語の途中で折り返さないため。「アクティブなシャード」などは 320〜345px と 840〜900px で「シャー/ド」と折り返した。320 / 375 / 768 / 840 / 880 / 900 / 1024 / 1145 / 1280px で語中の折り返しがないことを確認)。DS 4.10 の件数ブロックの形で、カード内用に小さくする(ラベル 12px、値 18px / 600、「うち移動中」は 12px の補足を値の右に同じ行で、余白 8px 16px。4 列、幅 840px 未満は 2 列)。領域の下に 1px の境界線を引き、マトリクスの凡例と区切る。

- `data-testid`: `o1-summary`(8 章)。

### 3.3 マトリクス(ノード×インデックスのシャード配置。カード「クラスタ状態」の下の領域。#23。**向き=行がノード・列がインデックス、とページングはユーザー指示 2026-11-22 で承認済み。以下の細部は案(PR レビューで確認)。「シャードの配置」は、この領域を指す説明用の語で、カードの見出し・名称ではない(カードの名称は「クラスタ状態」)**)

**構造(向きは承認済み。細部は案)**

- **行=ノード、列=インデックス**。行見出し(左端の列)がノード、列見出し(上端の行)がインデックス。各セルには、**そのノードに載っているそのインデックスのシャード**をチップで並べる。
- **行見出し(ノード)**: ノード名(等幅・600・折り返し可)+補足(12px)「シャード n」(そのノードに載っている、**表示対象のインデックス**分の合計。絞り込みなしなら全インデックス、**絞り込み中は絞り込み後のインデックス(全ページ)の合計**(3.5)。視覚的に隠した「(全インデックスの合計)」または「(絞り込み後のインデックスの合計)」を添える)。ノードの役割・ヒープ・負荷などは出さない(AF-17 は最小ビュー。要件にない情報で、取得に別の読み取りが要る)。クラスタの全ノードを行にする(シャードを持たないノードも出す。セルは「—」)。
- **未割り当ての行**: 未割り当てのシャードが**表示対象のインデックス(絞り込み中は絞り込み後。全ページ)に 1 つでもあるとき**(旧: クラスタに 1 つでもあるとき。絞り込みで変わる。3.5)、**最下部**に「未割り当て」の行を 1 つ出す(三角アイコン+「未割り当て」。補足「シャード n」は、**ノード行と同じく表示対象のインデックス(絞り込み中は絞り込み後・全ページ)の合計**。視覚的に隠した「(全インデックスの合計)」または「(絞り込み後のインデックスの合計)」を添える)。行の面は `warning-container`(40%)、上の区切りは点線(`warning`)。現在のページに該当のシャードがなくても行は残し、セルは「—」にする(ページを送っても行の構成を変えない。別のページに未割り当てがあることは、行見出しの合計から分かる)。固定位置は「最下部」(ノード行の後ろ)。
- **列見出し(インデックス)**: 上から ① インデックス名(等幅 12px・600・`overflow-wrap: anywhere`。2〜3 行に折り返す)、② **ドキュメント件数**(3.2。「12,846 件」。**名前の直下に出すこと、プライマリ数・レプリカ数の数値を出さないことはユーザー指示で承認済み**)、③ 状態タグ(3.1 の green / yellow / red。インデックスはタグの語のみ。**最下段に置くことは案**)。見出し行は `surface-variant` 面。名前の折り返しの行数が違っても、③は見出しの下端にそろえる(名前と件数を上寄せ、タグを下寄せ。件数の縦位置は名前の行数で列ごとにずれる=許容)。DOM・読み上げの順は 名前→件数→状態。
- **列見出しの「シャード n」(インデックスごとのシャード数)は外す**(案。旧案では出していた): **設計者の判断**(見出しを「名前・件数・タグ」の 3 要素に保つため。シャード数はその列のチップ数で見える)。ユーザーの発言(「プライマリ数やレプリカ数は…数値で表示する必要はない」)はプライマリ/レプリカ数についてで、**インデックスごとのシャード数には触れていない**ため、承認済みとは書かない。**ユーザー確認事項**。**行見出しの「シャード n」(ノードごとの全インデックスの合計)は残す**(ノード間の偏りを見るための情報で、チップを数えにくい。ユーザー指示の対象外)。残す案(件数の下に「シャード 2」を並べる)は、見出しが 4 要素になって高くなるため採らない。
- **システムインデックス**(名前が `.` で始まるもの)は、#22 のとおり**区別せず、通常のインデックスと同じ並び順・見た目**で出す(絞り込み・切替・特別な印は置かない)。
- **左端の行見出し列(ノード)は固定(`position: sticky; left: 0`)**にする。通常はページに収まるため横スクロールは出ないが、テキスト拡大・ブラウザの拡大などで列が収まらないとき、行見出しを残したまま列だけがスクロールできるようにする(保険。3.4)。固定した列は不透明な面(`surface` / `warning-container`)にし、右端に 1px の境界(`border`)を付ける。
- 角の見出し(左上)は「ノード」(`surface-variant` 面・12px / 600)。
- **表はカードの左右の端まで広げる**(カードの内側余白 16px を設けない)。凡例とページ送りバーだけが左右 16px(幅 600px 未満のバーは 12px)の余白を持つ。1 ページの列数の W は、この全幅(枠 1px×2 を除く)で測る(3.4)。
- 罫線: セルの区切りは 1px の薄い罫線(`border` の 8% 〜 16%)。縞模様にしない。行ホバーの強調はしない(行に操作がなく、固定した行見出しの面を不透明に保つため)。

**セルとチップ(承認済みの流儀に従う。色・形・文言は #23 のまま)**

- セルのシャードは**チップ**で示す。チップの文字は「P」(プライマリ)または「R」(レプリカ)+シャード番号(例: `P0`、`R1`)。1 つのセルに複数のシャードが並ぶときは、プライマリ → レプリカ、シャード番号の昇順で、横に並べて折り返す(セルの最小の高さ 48px)。

| 状態 | 見た目(色・形・文言) | 読み上げ(視覚的に隠した文) |
| --- | --- | --- |
| プライマリ(割り当て済み) | `primary-container` 面・実線の枠・太字の `P0` | 「(プライマリ。割り当て済み)」 |
| レプリカ(割り当て済み) | 白面・`line-strong` の実線の枠・`R0` | 「(レプリカ。割り当て済み)」 |
| 未割り当てのレプリカ | `warning-container` 面・点線の枠(`warning`)・三角アイコン+`R0` | 「(レプリカ。未割り当て)」 |
| 未割り当てのプライマリ | `error-container` 面・点線の枠(`error`)・八角形アイコン+`P0` | 「(プライマリ。未割り当て)」 |
| 初期化中・移動中 | `info-container` 面・実線の枠(`info`)・矢印アイコン+`P0` / `R0`(**初期化中と移動中は見た目を同一にする**。案。凡例も 1 項目「初期化中・移動中」) | 状態ごとに**読み上げを分ける**: 「(プライマリ。初期化中)」「(レプリカ。移動中)」など(案) |

- チップの枠線の色(プライマリの `primary` の 45%、移動中の `info` の 50%)は、背景に対して 3:1 に満たない。状態は**文字(P / R)・アイコン・枠の線種で伝え、色や枠線の濃さには依存しない**(WCAG 1.4.11 の「状態を示す図形」は、文字とアイコンでも伝えているため)。
- 凡例をマトリクス領域の上部に常に出す(チップの実物+説明)。凡例の項目は、**プライマリ・レプリカは常に、それ以外(未割り当てのレプリカ・未割り当てのプライマリ・初期化中/移動中)は、表示対象のデータ(絞り込み中は絞り込み後。全ページ)のどこかにその状態があるときだけ**出す(3.5)。ページを送っても凡例は変わらない。凡例にない状態のチップは出さない。
- そのノードにそのインデックスのシャードがないセルは「—」(視覚的に隠した「シャードなし」)。
- **全幅で同じ表**(行=ノード・列=インデックス)にする。DS 4.15 の旧規定「幅 840px 未満はインデックスごとのブロックに積む」は廃止(行がノードのため、列を 1〜2 に絞れば 320px でも収まる。3.4)。
- ノード行が多いとき(10 ノード超など)は、行が縦に伸びるだけで、行のページングはしない(MVP は単一ホスト・単一ノードが想定。ノードは多くても数台)。

### 3.4 列のページング(**ページングはユーザー指示で承認済み。具体値・部品構成は案(PR レビューで確認)**)

インデックスが増えるとカードに収まらなくなるため、**列(インデックス)をページで切り替える**。固定の行見出し(ノード)+列がカードの幅に収まるように、1 ページの列数を幅から決める(ページ全体・表内の横スクロールを出さない)。

**1 ページの列数(案)**

- 列数 = `max( 1, floor( (W − H) ÷ 112 ) )`(**上限は置かない**。理由は下の「根拠」)。**W = カード「クラスタ状態」の内容領域の幅(カードの枠 1px×2 を除く。マトリクスはカードの左右の端まで広がるため、概況を統合してもカードの幅・W・検算表は変わらない)**。マトリクスはカードの内側余白(16px)を設けず、カードの左右の端まで全幅に置く(凡例とページ送りバーだけが 16px の余白を持つ)。H = 行見出し列の幅(**viewport 幅 600px 以上は 152px、600px 未満(Vuetify の sm 未満)は 112px**)、112px = 列の最小幅。ページに収まるインデックスが 1 ページ分以下(総数 ≤ 列数)ならページングを出さない。
- 列幅は、ページングを出すとき `floor((W − H) ÷ 列数)` で**全ページ同じ**(最終ページの列が少なくても幅を変えず、右に余白を残す)。ページングがないときは `floor((W − H) ÷ インデックス数)`(上限 200px)。`table-layout: fixed`、列見出しのインデックス名と、セルのチップは折り返す。
- **根拠**: 112px = 等幅 12px・600 の名前(約 7.2px/字)が 2〜3 行に折り返しても読め、かつ 2 つのチップ(`P1` `R0` で約 80px)と左右の余白 16px が 1 行に入る最小の幅。H = 152px は、ノード名(`demo-node-1` で約 86px)に左右 12px と余裕を足した値(600px 未満は 112px: 狭い幅で列を 1 つでも多く残すため。「未割り当て」の見出しが折り返さない最小。行見出しの左右余白は 600px 以上が 12px、未満が 8px)。**列数に上限は置かない**(案): 式で列幅は常に 112px 以上になるため、上限は 112px 割れの防止にならない。上限(10 とした場合)が効くのは W が 1,384px 以上(列数 11 以上)のときだけで、コンテンツ幅の上限 1400px(DS 2.3)でも 11 列にしかならない。得られる利点が小さいので、規則を 1 つ減らす。
- **列見出しが「名前+件数+状態タグ」の 3 要素になっても 112px で収まるか(検証済み。案)**: 見出しの内側は 96px(左右余白 8px)。名前は折り返せる(2〜3 行)。状態タグ(yellow で約 70px)・件数(9 桁まで 91px 以下)は 1 行に収まる(10 桁以上は件数の単位だけ折り返し、見出しの高さが 1 行ぶん増える。3.2)。実測(モック、macOS のシステムフォント。幅 320〜1280px、全ページ・全状態): はみ出し・横スクロールなし。見出しの高さは 82〜115px。**よって列幅の最小値 112px・H=152/112px・列数の式・検算表は変えない**(幅は macOS のシステムフォントでの実測。他の OS では実機で要確認)。
- 閾値ではなく**式**にした理由: カード幅は viewport からサイドバーの有無と余白を引いた値で、画面の最大幅でも変わる(DS 4.3 の「viewport ではなくカード幅で決める」と同じ方針)。実装は、要素の幅を測る(`ResizeObserver` を使う小さな composable。VueUse を使う場合は DS 10 章の依存に足す)で同じ式を使う。
- 実アプリでの目安(カード幅 = viewport − サイドバー 232px − 左右の余白(DS 2.3・5.1)。W = カード幅 − 枠 2px(1px×2)。クラシックなスクロールバー(約 15px)がある環境では、さらに 15px 引く): 

| viewport | カード幅 | W(枠 2px を除く) | H | (W − H) ÷ 112 | 1 ページの列数 |
| --- | --- | --- | --- | --- | --- |
| 1280px | 984px | 982px | 152 | 7.41 | **7** |
| 1145px | 849px | 847px | 152 | 6.20 | 6 |
| 1024px | 744px | 742px | 152 | 5.27 | 5 |
| 840px | 560px | 558px | 152 | 3.63 | 3 |
| 768px(サイドバーなし) | 736px | 734px | 152 | 5.20 | 5 |
| 375px | 343px | 341px | 112 | 2.04 | 2 |
| 320px | 288px | 286px | 112 | 1.55 | 1 |

  スクロールバー分(15px)を引いても、列数は 7・6・5・3・5(375px 以下はオーバーレイのスクロールバーで影響なし)のまま変わらない(768px が 5.06 でもっとも余裕が小さい。続いて 1145px が 6.07)。  
  モックで確認した値: 1280 → 7、1145 → 6、1024 → 5、840 → 3、768 → 5、375 → 2、320 → 1。モックの画面枠には 1px の枠があるため、W は表の値より 2px 小さい(列数は同じ)。375px・320px では、インデックスが 3 件でもページングが出る(列が 2・1 のため)。これは意図した動き。

**ページ内の並び順(案)**

- **状態の悪い順(red → yellow → green → 未知の値)、同じ状態の中は名前の昇順**(コードポイント順)。ユーザーによる並べ替えは**置かない**(旧版の「インデックス」カードの表にあった名前・件数の並べ替えは、一覧の廃止とともになくなる。マトリクスは配置を見る場所で、操作を増やさない。トレードオフは 10 章)。並び順は、ページ送りバーの補足に常に書く(「インデックス名の下の数はドキュメント件数。状態の悪い順(同じ状態は名前の昇順)」)。
- **理由**: 調査の目的(未割り当て・red / yellow のインデックスがどのノードにあるか)では、問題のあるインデックスが**先頭のページに集まる**ほうが見つけやすい。未割り当てのシャードを持つインデックスは通常 yellow か red のため、最下部の「未割り当て」の行の内容は 1 ページ目で見えやすい(異常なインデックスが 1 ページの列数を超えるときは、次のページにも出る)。名前の昇順のみだと、問題のインデックスが後ろのページに隠れる。
- 代替: 名前の昇順のみ(予測しやすい。旧「インデックス」カードの既定の並びと同じ。ただし後ろのページの異常に気づきにくい)。ユーザーの確認事項。
- 件数の多い順など、並びを切り替える操作は置かない(MVP。後続設計の検討事項)。件数が大きいインデックスを探すときは、ページを送って列見出しの件数を読む(10 章のトレードオフ)。

**ページ送りバー(案)**: カード「クラスタ状態」の中の、マトリクス領域の凡例の下・表の上に置く(1 行。幅が足りなければ折り返す)。

```text
1–7 / 全 25 件のインデックス                     [‹ 前へ]  ページ [1 / 4 ▾]  [次へ ›]
インデックス名の下の数はドキュメント件数。 状態の悪い順(同じ状態は名前の昇順)。
(件数「—」の列があるとき)見出しの「—」は件数を取得できません。
```

- 左: 「a–b / 全 N 件のインデックス」(600)+補足(12px。**2 文に分け、文の途中で折り返さない**: 「インデックス名の下の数はドキュメント件数。」「状態の悪い順(同じ状態は名前の昇順)。」。現在の表示列に件数「—」があるときだけ、3 文目「見出しの「—」は件数を取得できません。」を足す)。**補足は、ページングの有無にかかわらず常に出す**(ボタン・セレクトだけを出さない)。ページングがないときの件数表示は「N 件のインデックス」。**絞り込み中の件数表示(3.5。N=絞り込み後、M=全件)**: 「a–b / 絞り込み後 N 件のインデックス(全 M 件中)」(1 ページに収まるときは「絞り込み後 N 件のインデックス(全 M 件中)」)。「(全 M 件中)」は 1 つの塊として扱い、途中で折り返さない。**一致 0 件(N=0)**は「絞り込み後 0 件のインデックス(全 M 件中)」だけを出し(件数表示の要素は消さない)、**補足は「適用中の条件: …」の文だけ**にする(上の「補足は常に出す」の例外)。凡例・ページ送りのボタン・表は出さない。絞り込み中は補足に「適用中の条件: …。概況はクラスタ全体の値で、絞り込みの対象外。」を足す。列数の式・列幅は、絞り込みでも変わらない。**件数表示(`role="status"`)は、常に DOM に存在し続ける**(絞り込み・ページ送り・0 件でも要素ごと消さず、中の文だけを書き換える。ライブリージョンの通知が確実に届くため)。
- 右: 「前へ」「次へ」(outlined・小型。シェブロン+文字。高さ 32px、幅 600px 未満は 44px)と、**ページ選択**(`select`。選択肢は「n / 全ページ数」。ページ数が多くても 1 つの部品で済む)。幅 600px 未満では、ページ選択の「ページ」のラベルを視覚的に隠し(読み上げは残す)、3 つの部品を **320px で 1 行に収める**(各 44px。この幅では「前へ」「次へ」の左右の余白を 10px、部品の間隔を 6px、ページ選択の幅を 84px に詰める)。算術: 前へ 約 72px+選択 84px+次へ 約 72px+間隔 12px=約 240px(実測 244px)≦ バーの内側 約 262px(320px のカード幅 288px − 枠 2px − バーの左右余白 12px×2)。ページ番号のボタン列は置かない(ページ数が 25 以上になりうるため)。
- 1 ページ目は「前へ」、最終ページは「次へ」を**使えない状態**にする(`aria-disabled="true"`。見た目は DS の無効ボタン。`disabled` にしない: 押した直後に無効になってもフォーカスが失われないため)。使えない状態のボタンを押しても何も起きない。**実装の注意**: `VBtn` は `aria-disabled` を透過するが、クリックイベントは発火する(`disabled` ではないため)ので、ハンドラの先頭で端のページを判定して何もしない(ガードする)。実機 Vuetify 4.3.4 で要確認。
- ページ送りで表だけを入れ替え、フォーカスは押したボタンに残す。スクロール位置は動かさない。
- **更新・幅の変化**: 「更新」で再取得したとき、表示中の先頭のインデックスを含むページを保つ(そのインデックスがなくなっていれば、最終ページに丸める)。ウィンドウ幅の変化で列数が変わったときも、表示中の先頭のインデックスを含むページにする。

**状態(マトリクスの出し分け。案)**

| 状態 | 見せ方(モック) |

**横スクロールの扱い(案)**: 列数を幅から決めるため、通常は**ページ全体・表内とも横スクロールは出ない**(全幅 320〜1280px で確認)。例外はブラウザの拡大・文字サイズ拡大などで、決めた列数が収まらなくなったとき(幅の再計測の前の一瞬を含む)。このときは表の外側(`overflow-x: auto`)だけがスクロールし、**行見出し(ノード)は固定されたまま**になる。スクロールできるときだけ、そのスクロール領域に `tabindex="0"`・`role="region"`・`aria-label="シャードの配置(横にスクロールできます)"` を付ける(通常は付けない)。

### 3.5 絞り込みフォーム(#37。O1 への指示の 4 回目。**「表示するインデックスをフィルタリングするフォームを追加すること」はユーザー指示で承認済み。以下の条件の種類・置き場所・適用のしかたなど具体値はすべて案(PR レビューで確認)**)

マトリクスに表示するインデックス(列)を絞り込む。ユーザーは条件の種類を指定していないため、MVP として最小の案を設計者が決めた。

**条件(案)**

- **インデックス名**: テキスト入力。**部分一致、大文字小文字は区別しない**(前後の空白は除く)。例: `logs` で `demo-logs-2026.11.01` などに一致。
- **状態**: green / yellow / red の**複数選択**(チェックボックス 3 つ)。何も選ばなければ「すべて」。選んだ状態のいずれか(OR)。
- 名前と状態は AND。条件の指定は 0〜2 種類。
- **システムインデックス(`.` で始まるもの)の表示切替は追加しない**(案): #22(承認済み)がシステムインデックスを区別しない方針で、切替は要件にない条件の追加だから。名前の一部一致では「`.` で始まる」だけを抽出できず、除外もできないが、MVP では許容する(後続設計の検討事項。必要になれば条件の配列(下の拡張点)に 1 行足せる。影響: #22 の「区別しない」を改訂する)。10 章の検討行も参照。
- **エッジケースの規則(案)**:
  - **名前**: 前後の空白は除き、**空白だけなら条件なし**。文字列の一致で、**正規表現ではない**(`.` や `*` はそのままの文字)。
  - **状態を 3 つとも選択**: 「すべて」と同じ=**条件なしに正規化する**(チェックの表示は 3 つ選んだまま。「条件を解除」は `aria-disabled` のまま、件数表示・補足も絞り込み前の文言)。
  - **未知の状態値のインデックス**(green / yellow / red 以外。3.1 の中立のタグで表示するもの): **状態を 1 つでも選ぶと(3 つとも選んだ場合を除く)除外**する。何も選ばないとき(3 つとも選んだ場合を含む)だけ表示する。
  - **IME の変換中**: debounce を始めず、**確定(`compositionend`)後に適用する**。
  - **直前に適用した条件と同じなら何もしない**(正規化後に比べる。マトリクスの 1 ページ目に戻らず、ページ位置を保つ)。例: 条件がないまま Enter、1 文字入れて消す、空白だけを入れる。
- **追加しない条件**: ノード、シャード数、ドキュメント件数の範囲など(要件にない機能)。**拡張点**: 条件は 1 つの配列(名前・状態)で定義し、画面側の `filter` の述語に畳む。後続設計で条件を足すときは、配列に行を足し、フォームに項目を足し、URL のクエリを足す。

**置き場所(案)**: カード「クラスタ状態」の中で、**概況の下・マトリクス領域の上(凡例の上)**。概況は絞り込みの対象外(クラスタ全体の状態のまま)で、領域として分け(境界線)、フォームの下に絞り込みの対象(凡例・件数表示・表)を続ける。理由: フォームを操作すると下の領域が変わるため、上から「全体(概況)→ 条件 → 結果」の順に並べる。フォームを表の下や横に置くと、操作と結果が離れる・列の幅(W)が減る。

**フォームの構成(案。DS 4.6 のフォーム項目・DS 4.1 のタグを再利用。新部品なし)**

- `<form role="search" aria-label="インデックスの絞り込み">`(`data-testid="o1-filter"`)。
- **インデックス名**: ラベル「インデックス名」(上に表示。12px)+テキスト入力(高さ 40px、幅 600px 未満は 44px。幅 280px、600px 未満は全幅)。プレースホルダは「名前の一部(例: logs)」(`on-surface-variant`)。視覚的に隠した説明「大文字小文字は区別しません。入力するとすぐに絞り込みます。」を `aria-describedby` で結ぶ。`autocomplete="off"`、`spellcheck="false"`。
- **状態**: `fieldset`+`legend`「状態(複数選択できます。選ばなければすべて)」(12px)+チェックボックス 3 つ。各ラベルは**状態タグ**(3.1。色・形・文言)で、順は red → yellow → green(マトリクスの並び順と同じ)。チェックボックスの大きさ 18px、ラベル全体を押せる(高さ 40px、600px 未満は 44px)。
- **条件を解除**: 小型の text ボタン(高さ 32px、600px 未満は 44px)。
- 並び: 幅 1145px 以上は 1 行(フォームの高さ 86px)。幅が足りないときは折り返す(**1024px・768px で 126px、600px・840px・900px で 151px**)。幅 600px 未満は縦に積む(名前→状態→解除。各部品 44px)。**375px は状態のチェック 3 つが 1 行で、フォームの高さ 219px。320px は状態のチェックが 2 行+1 行に折り返し、高さ 263px(この折り返しを含む)**。測定条件: モックの実測(Chromium、macOS のシステムフォント、1 回。他の OS・フォントでは幅が変わりうる)。
- **縦の増加の評価(案。モックの実測。`#o1-paging`、yellow の概況)**: **1280px(高さ 900px の画面)**: ページ上端から表の上端まで約 540px(カード上端 73px+カード内 465px。うちフォーム 86px)で、フォームを足しても、表の列見出しと最初の数行が 1 画面に入る。**375px(高さ 800px)**: 表の上端は約 970px(カード上端 169px+カード内 797px。うち概況 289px・フォーム 219px)で、**最初の 1 画面の外になる**(フォームがない場合は約 750px で収まっていた)。320px も同様(約 1030px)。DS の前提(デスクトップ優先。768px・375px は崩れない最低限)の範囲だが、狭い幅ではスクロールが 1 画面ぶん増える。許容するかは**ユーザー確認事項**(許容しない場合の後続設計の案: 狭い幅でフォームを折りたたみ式にする)。

**適用のしかた(案)**

- **即時に絞り込む**。名前は入力に応じて **250ms の debounce**、**Enter ですぐ**(フォームの送信は止め、ページは移動しない)。状態はチェックの切替ですぐ。**「絞り込む」ボタンは置かない**(データが画面側にあり、絞り込みは瞬時にできる。ボタンは操作を 1 つ増やす)。
- **条件を解除**: すべての条件を外し(名前の入力欄を空に、チェックを外す)、**名前の入力欄にフォーカスを移す**。条件が 1 つもないときは `aria-disabled="true"`(押しても何も起きない。フォーカスは残る)。**ボタンは画面に 1 つだけ**(一致 0 件のブロックには置かない。同じ名前のボタンが 2 つになると、ロールとラベルでの特定が一意にならないため)。
- 条件を変えたら**マトリクスは 1 ページ目に戻る**(ただし条件が変わらないときは何もしない。上のエッジケース)(列数・列幅・並び順(状態の悪い順→名前昇順)は変わらない)。「更新」(再取得)や幅の変化では、条件・入力を保つ(ページ位置は 3.4 の規則)。

**結果の表示(案)**

- **件数表示(`role="status"` `aria-live="polite"`)が結果件数を通知する**: 条件を変えて件数表示が変わると読み上げられる(「絞り込み後 3 件のインデックス(全 25 件中)」。一致 0 件は「絞り込み後 0 件のインデックス(全 25 件中)」)。名前の入力中は、1 文字ごとには読み上げない(250ms の debounce)。表示する文が変わったときだけ内容を書き換える。表示は 3.4。**N=絞り込み後、M=全件**で、絞り込み前の総数が分かる(「全 M 件中」)。「(全 M 件中)」は 1 つの塊として扱い、句の途中で折り返さない(`inline-block`)。
- **適用中の条件の表示**: 件数表示の「絞り込み後」と、補足の「適用中の条件: 名前に「logs」を含む、状態が yellow または green。概況はクラスタ全体の値で、絞り込みの対象外。」。フォームの入力欄・チェックが条件そのものを示し、解除はフォームのボタン(別に条件のチップは出さない)。
- **マトリクス**: 列=一致したインデックスだけ。並び順は変わらない。
  - **行見出し「シャード n」(ノード行・未割り当て行)は、絞り込み後のインデックス(全ページ)の合計**(推奨。理由: マトリクスは絞り込み後の配置を表すため、行見出しの数をセルのチップの合計と一致させる)。クラスタ全体の合計にしない。**概況の件数(クラスタ全体のまま)とは、絞り込み中は値が違いうる**。違いは、補足の「概況はクラスタ全体の値で、絞り込みの対象外。」と、行見出しの視覚的に隠した「(絞り込み後のインデックスの合計)」で示す。
  - **未割り当ての行**は、絞り込み後のインデックスに未割り当てのシャードがあるときだけ出す。
  - **凡例**は、絞り込み後のデータにある状態だけを出す(推奨。3.3 の規則を、表示対象を絞り込み後にして適用する)。
- **一致 0 件(規則。案)**: **件数表示(`role="status"`。常に DOM にあり、要素ごと消さない)に「絞り込み後 0 件のインデックス(全 M 件中)」だけを出し、補足は「適用中の条件: …」の文だけ**にする(3.4 の「補足は常に出す」の例外)。凡例・ページ送りのボタン・表は出さない。代わりに、DS 4.5 の空のブロックを再利用して、見出し「条件に合うインデックスがありません」+説明「インデックス名や状態の条件を変えるか、上のフォームの「条件を解除」で条件を外してください。」を出す(`o1-state-nomatch`)。**ブロックに「条件を解除」ボタンは置かない**(フォームのボタンが同じ画面にあり、ボタンが 2 つになると `getByRole` での特定が一意にならないため)。同じ内容を 2 回出さない(件数表示は件数だけ、ブロックは見出しと説明だけ)。フォームはそのまま使える。
- **概況は絞り込みの対象外**(クラスタ全体の状態を見せ続ける)。

**URL への反映(案)**: クエリ `q`(インデックス名)・`state`(カンマ区切り。例 `?q=logs&state=yellow,green`)で条件を持つ。J1(`source`・`status`・`page`)・X1(`source`・`tab`・`page`)が、一覧の状態を URL のクエリに持ち、再読み込み・共有で再現する流儀に合わせる。入力に追随して `router.replace`(履歴を増やさない。名前は debounce の後)で更新する。再読み込み・共有で条件を復元する。**マトリクスのページ位置(`page`)は URL に入れない**(1 ページの列数が幅で決まるため、同じ URL でも幅によって意味が変わる)。未知の `state` の値は無視する。実アプリの仕様で、静的なモックは URL に反映しない。**URL に条件が残ったままインデックスが 0 件になった場合**(フォームは出さない)は、URL の条件を保持する(消さない。インデックスが戻れば再び絞り込まれる)。**初回の読み込み中**は、URL から復元した条件(名前・状態)を、無効のフォームに表示する(読み込み後に値が突然現れないように)。

**状態ごとのフォーム(案)**: 4 章を正とする(インデックス 0 件・エラー=出さない、読み込み中=無効のまま出す、stale・再取得中=使える)。

**実装**: 絞り込みは画面側(`filter`。インデックスは数十〜数百件の想定)。Admin API は変更しない(全件を返す。9 章)。Vuetify の `VTextField`・`VCheckbox`(ラベルに状態タグ)・`VBtn`(text)で足りる(新しい UI ライブラリは不要)。読み取り専用のまま(変更操作・Loreley 固有の概念は置かない)。**実機 Vuetify 4.3.4 で要確認**: `VTextField` の高さ(`density` の指定が要る。入力 40px / 600px 未満 44px にそろえる)、`aria-describedby` の `id` が複数の画面・部品で衝突しないこと、「条件を解除」の `aria-disabled` の押下(`VBtn` は属性を透過するがクリックは発火するため、ハンドラでガードする。3.4 と同じ)、`VCheckbox` のラベルスロットに状態タグを入れたときのアクセシブルネーム(アイコンは `aria-hidden`、ラベルは状態の語だけになること)。

## 5. インタラクション

- 更新: 「更新」ボタン(手動のみ。承認済み(ゲート C。#22))。更新中も表示は残し、進行バーのみ(DS 4.5)。
- 絞り込み(案。3.5): 名前の入力は 250ms 待ってから絞り込む。Enter ですぐ(ページ移動なし)。状態のチェックの切替ですぐ。「条件を解除」で全条件を外し、名前の入力欄にフォーカスを移す。条件を変えるとマトリクスは 1 ページ目に戻る。アニメーションなし。Tab の順は 名前 → 状態(red・yellow・green)→ 解除 → ページ送り。ショートカットキーは置かない。
- ホバー: シャード配置のマトリクスの行・列は強調しない(3.3)。操作要素のフォーカスリングは DS 2.6。
- インデックス名・チップは操作できない(読み取り専用)。クリックで詳細に移る動きは置かない(AF-28 で足す)。
- シャードの配置のページ送り(案。3.4): 「前へ」「次へ」「ページ選択」で表を入れ替える。アニメーションなし(表をそのまま差し替える)。フォーカスは操作した部品に残る。ショートカットキー(矢印キーでページ送りなど)は置かない。使えない端のボタンは `aria-disabled`(押しても何も起きない)。

## 7. アクセシビリティ

- 見出し: `h1`「OpenSearch」。カードの見出しは `h2`「クラスタ状態」(1 つだけ。2 カードの版では「クラスタの状態」「シャードの配置」の `h2` が 2 つ)。**階層は `h1` → `h2` 1 つ。例外: エラーブロックと空のブロックのカード内 `h3`**(DS 4.5 の状態ブロックの見出し。空のブロックも `h3` のままにする理由: 状態ブロックの部品を共通にし、エラー・空で見出しの扱いを変えないため)。概況・絞り込みフォーム・マトリクスの領域には見出しを置かない。**領域は、検索ランドマーク(絞り込みフォームの `role="search"`)、ラベルつきグループ(マトリクスの領域だけ `role="group"`)、`dl`(概況のラベルと値の対)で区別する**。
- **`aria-labelledby` の参照先は、常に `h2` の文言(「クラスタ状態」)だけ**: 前回データ表示の注記(「前回取得時の値 · 最終更新(成功)…」)は、`h2` の外の、見出し行の右の別要素にする(`h2` の中に入れると、`h2` とカードのアクセシブルネームに注記が連結される)。
- **カードの名前・読み上げ順(案)**: カードは `<section aria-labelledby>`(`h2` を参照。状態によらず同じ。エラー・読み込み中も)。順は 見出し「クラスタ状態」→ 概況(クラスタ名・状態・説明・件数 4 項目。`dl` のラベルと値の対)→ **絞り込みフォーム(`role="search"` の検索ランドマーク。状態は `fieldset`+`legend`。3.5・次の項目)**→ マトリクス領域(`role="group"` `aria-label="シャードの配置(行はノード、列はインデックス)"`: 凡例 → ページ送りバーの件数(`role="status"`)・補足 → ページ送りの 3 部品 → 表(`caption`))。概況の状態タグは、色・形・文言(3.1)。
- 状態タグは色・形・文言(green / yellow / red の文字)。シャードのチップは文字(P / R)・枠の線種・アイコンで区別し、状態を視覚的に隠した文でも読み上げる。
- **シャードの配置の表(案)**: `<caption>`(視覚的に隠す)に向きと位置を書く(「シャードの配置。行はノードと未割り当て、列はインデックス(列見出しにインデックス名・ドキュメント件数・状態)。全 N 件のうち a〜b 件目を表示中(ページ p / P)。状態の悪い順、同じ状態は名前の昇順。」)。並べ替えはないため `aria-sort` は付けない。列見出しの件数は、見出しセルの中のテキストとして、名前→件数→状態の順に読み上げられる(「demo-docs-000001 ドキュメント 12,846 件 green」。取得不能は「ドキュメント件数を取得できません」)。**列見出しの読み上げが冗長なときは、件数を見出しの外に出して `aria-describedby` で結ぶなどで分ける(実機のスクリーンリーダーで要確認)**。角と列見出しは `<th scope="col">`、ノードと未割り当ての行見出しは `<th scope="row">`(スクリーンリーダーが、セルを「ノード名・インデックス名」で読み上げられる)。空のセルは「—」+視覚的に隠した「シャードなし」。チップの状態の読み上げは本章の上の項目のとおり。
- **ページ送り(案)**: ボタンとセレクトを `role="group"` `aria-label="シャードの配置のページ送り"` で囲む。「前へ」「次へ」のアクセシブルネームは、見える文字を含める(`aria-label="前へ。シャードの配置の前のページ"`、`"次へ。シャードの配置の次のページ"`。何のページ送りかを読み上げで分かるようにするため)。ページ選択は `<label>`「ページ」(幅 600px 未満では視覚的に隠すが、読み上げは残す)付きの `select`(選択肢「n / 全ページ数」)。1 ページ目の「前へ」・最終ページの「次へ」は `aria-disabled="true"`(フォーカスは残る)。
- **現在位置・結果件数の通知(案)**: 件数表示(「a–b / 全 N 件のインデックス」。絞り込み中は「a–b / 絞り込み後 N 件のインデックス(全 M 件中)」。**N=絞り込み後、M=全件**)の要素を `role="status"` `aria-live="polite"` `aria-atomic="true"` にし、視覚的に隠した「(ページ p / P)」を含める。ページ送りのたびに読み上げられる(初回表示では読み上げない)。更新・幅の変化に伴う再計算では、**ページまたは表示範囲(a–b)が変わったときだけ**内容が変わる(同じ内容なら読み上げない)。表示範囲が 1 件だけのとき(最終ページが 1 列など)は「25 / 全 25 件のインデックス」の形にする(「25–25」としない)。
- **絞り込みフォーム(案。3.5)**: `<form role="search" aria-label="インデックスの絞り込み">`(検索のランドマーク。カード内の 1 つだけ)。名前の入力は `<label>`「インデックス名」付きで、視覚的に隠した説明を `aria-describedby` で結ぶ。状態は `fieldset`+`legend`(「状態(複数選択できます。選ばなければすべて)」)+チェックボックス 3 つ(ラベルは状態タグ=色・形・文言。チェックの有無はネイティブのチェックボックスの状態で伝わる。色だけに頼らない)。「条件を解除」は条件がないとき `aria-disabled="true"`(フォーカスは残る)。**結果件数の通知**: 件数表示(`role="status"` `aria-live="polite"` `aria-atomic="true"`。次の項目)が、絞り込みで内容が変わるたびに読み上げる(「絞り込み後 3 件のインデックス(全 25 件中)」。一致 0 件は「絞り込み後 0 件のインデックス(全 25 件中)」)。名前の入力中は、1 文字ごとには読み上げない(250ms の debounce)。**件数表示の要素は、0 件でも消さず、常に DOM に存在し続ける**(中の文だけを書き換える)。フォーカスは動かさない(解除のときだけ名前の入力欄へ)。読み込み中の無効のフォームは `disabled`(無効の入力欄の見た目。DS 4.6)。
- キーボード(案): 絞り込みフォームの Tab の順は 名前の入力 → 状態(red・yellow・green。Space で切替)→ 条件を解除(Enter・Space)。名前の入力で Enter はすぐ絞り込む。続けて、「前へ」→ ページ選択 → 「次へ」→ 表(表は操作要素を含まない。収まらず横スクロールが出ているときだけ表のスクロール領域も Tab で到達できる)。Enter・Space でボタン、ページ選択は矢印キーで選ぶ。ショートカットキーは置かない(WCAG 2.1.4 を避けるため)。
- タップ領域: 絞り込みフォームの名前の入力・チェックボックスのラベル全体・解除は、幅 600px 未満で高さ 44px(それ以上も入力 40px・チェックのラベル 40px・解除 32px で 24px 以上。2.3)。ページ送りの 3 部品は幅 600px 未満で高さ 44px(2.3)。**320px で 1 行に収まる**(3.4 の算術: 約 240px ≦ バーの内側 約 262px。余白・間隔は 320px まで詰めた値)。
- red のアラートは `role="status"`(読み込み後の情報)、取得失敗は `role="alert"`。自動更新はないため、`aria-live` は更新結果の通知に使わない。
- 配色のコントラストは DS 2.1 の値(on-container 文字は 4.5:1 以上)。点線の枠は装飾ではなく状態を示すが、アイコンと文字でも伝える。

## 8. `data-testid`

**`o1-cluster`(カード「クラスタ状態」全体。旧: 「クラスタの状態」カード)、`o1-summary`(概況の領域。新規)、`o1-shards`(マトリクスの領域。旧: 「シャードの配置」カード。カードの中の領域に付け替え)**、`o1-count-{インデックス名}`(列見出しのドキュメント件数。`o1-indices` は「インデックス」カードの廃止とともに廃止)、**`o1-filter`(絞り込みフォーム。新規)、`o1-state-nomatch`(絞り込みの一致 0 件のブロック。新規。カード内)**、`o1-state-empty` / `-error` / `-stale` / `-loading`。絞り込みの入力・チェック・解除は、ロールとラベルで特定する(`getByRole('textbox', { name: 'インデックス名' })`(入力の種類は `type="text"`)、`getByRole('checkbox', { name: 'yellow' })`、`getByRole('button', { name: '条件を解除' })`。入力・チェック・解除には `data-testid` は付けない)。**件数表示(`role="status"`)には `data-testid="o1-count"`**(絞り込み後の件数表示の文を確認するため。新規)。ボタンはロールとラベルで特定する(DS 9)。シャードの配置のページ送りの 3 部品は、`getByRole('group', { name: 'シャードの配置のページ送り' })` の中のボタン・セレクトで特定でき、`data-testid` は付けない。マトリクスの表は `o1-shards` の中の `table` で特定する(案)。**状態の表示(`o1-state-*`)は、全状態でカード `o1-cluster` の中に付ける**(案): `o1-state-loading` = カード内の読み込み中の通知(`role="status"`)、`o1-state-error` = カード内のエラーブロック、`o1-state-empty` = カード内の空のブロック、`o1-state-stale` = 見出し行の右の「前回取得時の値」の注記。カード外のラッパー(`stack` など)に付ける案は採らない: ラッパーはカードと並ぶ警告アラート(stale)なども含み、「状態はカード内の領域単位」という方針(4 章)と合わなくなるため。取得失敗(データなし)のエラーブロックも、カードを置き換えず、カードの中に出る。
