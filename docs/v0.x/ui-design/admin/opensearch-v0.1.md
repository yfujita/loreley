## 1. 目的・主要操作

- 利用者(管理者)が、OpenSearch のクラスタが健全か(green / yellow / red)、どんなインデックスがありドキュメントが何件か、シャードがどのノードに配置されているかを確認する(AF-17)。検索が遅い・失敗するといったとき、またダッシュボード(D1)で opensearch の異常を見たときの調査先。
- 主操作はなし(読み取り専用)。操作は「更新」(outlined)のみ。
- テンプレート: ダッシュボード(`dashboard`。読み取り専用の概況。DS 6.4)。route: `/opensearch`。ナビの現在地は「OpenSearch」。
- route `meta`: `../admin-view-v0.1.md` 4.2 の表のとおり(`title: 'OpenSearch'`、`template: 'dashboard'`、`nav: { label: 'OpenSearch', icon: mdiServer, group: 'inspect', order: 1 }`)。値は 4.2 を正とし、本書では繰り返さない。

## 3. コンポーネント

| 領域 | 部品 | 内容 |
| --- | --- | --- |
| クラスタの状態 | カード+`KeyValueList`(DS 4.4)+件数ブロック(DS 4.10。4 項目) | クラスタ名(等幅)、状態(タグ+説明)、ノード数、アクティブなシャード数、未割り当てのシャード数、初期化中・移動中のシャード数 |

| シャードの配置 | カード+凡例+`ShardMatrix`(DS 4.15。新規。承認済み(ゲート C)) | 行=インデックス、列=ノード(+未割り当て) |
| 状態 | 空・エラー・読み込み・古いデータ(DS 4.5) | 6 章 |

### 3.1 クラスタ・インデックスの状態タグ(DS 4.1 に追加)

| 値 | タグ | 色 | アイコン(`@mdi/js`) | 説明(クラスタ。承認済み(ゲート C。#23)) |
| --- | --- | --- | --- | --- |
| green | 「green(正常)」(インデックスは「green」) | `success-container` | `mdiCheckCircleOutline`(円) | すべてのシャードが割り当てられています。 |
| yellow | 「yellow(注意)」 | `warning-container` | `mdiAlertOutline`(三角) | プライマリシャードはすべて割り当てられていますが、一部のレプリカシャードが割り当てられていません。単一ノードでレプリカが 1 以上のインデックスは、通常 yellow になります。 |
| red | 「red(異常)」 | `error-container` | `mdiCloseOctagonOutline`(八角形) | 一部のプライマリシャードが割り当てられていません。該当するインデックスの検索や登録に影響する可能性があります。 |

- 値の語(green / yellow / red)は OpenSearch の語彙をそのまま使う(管理者が OpenSearch のドキュメント・Dashboards と対応づけられるように)。
- 未知の値は中立のタグ(アイコンなし)+値をそのまま表示する(`StatusTag` の規約。DS 4.1)。
- red のとき(取得は成功している)ページ上部に error のアラート(`role="status"`)「未割り当てのプライマリシャードがあります」+該当するインデックスとシャード番号を出す(モック `#o1-red`)。yellow ではアラートを出さず、カード内の説明だけにする(単一ノードでは通常の状態のため、通知を出し過ぎない)。

### 3.2 インデックス一覧の列

| 列 | 内容 | 表示 | 並べ替え |
| --- | --- | --- | --- |
| インデックス名 | 名前 | 等幅・折り返す | 昇順(既定)・降順 |
| 状態 | green / yellow / red のタグ(3.1) | | なし |
| ドキュメント件数 | ドキュメント数 | 右揃え・3 桁区切り | 昇順・降順 |
| プライマリ | プライマリシャード数 | 右揃え | なし |
| レプリカ | レプリカ数 | 右揃え | なし |

- Loreley 固有の意味づけ(「検索インデックス」「ジョブ記録」など)は付けない。名前をそのまま表示する。行にリンク・操作はない。
- 件数が少ない一覧として、クライアント側ページング(既定 25 件)。

### 3.3 シャードの配置(承認済み(ゲート C。#23))

- 行はインデックス(行見出し。等幅)、列はノード名(等幅)。未割り当てのシャードがあるときだけ、右端に「未割り当て」の列を出す。
- セルのシャードは**チップ**で示す。チップの文字は「P」(プライマリ)または「R」(レプリカ)+シャード番号(例: `P0`、`R1`)。1 つのセルに複数のシャードが並ぶときは横に並べて折り返す。

| 状態 | 見た目(色・形・文言) | 読み上げ(視覚的に隠した文) |
| --- | --- | --- |
| プライマリ(割り当て済み) | `primary-container` 面・実線の枠・太字の `P0` | 「(プライマリ。割り当て済み)」 |
| レプリカ(割り当て済み) | 白面・`line-strong` の実線の枠・`R0` | 「(レプリカ。割り当て済み)」 |
| 未割り当てのレプリカ | `warning-container` 面・点線の枠(`warning`)・三角アイコン+`R0` | 「(レプリカ。未割り当て)」 |
| 未割り当てのプライマリ | `error-container` 面・点線の枠(`error`)・八角形アイコン+`P0` | 「(プライマリ。未割り当て)」 |
| 初期化中・移動中 | `info-container` 面・実線の枠(`info`)・矢印アイコン+`P0` / `R0` | 「(プライマリ。移動中)」など |

- 凡例をカード上部に常に出す(チップの実物+説明)。凡例にない状態のチップは出さない。
- そのノードにシャードがないセルは「—」(視覚的に隠した「シャードなし」)。
- 幅 840px 未満(積み表示): インデックスごとにブロックにし、「ノード名: チップ…」の行を並べる。シャードのないノード(空のセル)の行は出さない。
- ノード数が多く(目安 5 以上)幅に収まらないとき: ノード列の表だけを横スクロール(表内スクロールの例外。インデックス名の列は固定)。MVP は単一ホスト・単一ノードが想定で、この場合の最適化は行わない(#23 の代替を参照)。

## 7. アクセシビリティ

- 見出し: `h1`「OpenSearch」。カードの見出しは `h2`(「クラスタの状態」「インデックス」「シャードの配置」)。
- 状態タグは色・形・文言(green / yellow / red の文字)。シャードのチップは文字(P / R)・枠の線種・アイコンで区別し、状態を視覚的に隠した文でも読み上げる。
- 表: `<caption>`(視覚的に隠す)、`<th scope="col">`、行見出し(`scope="row"` のインデックス名。シャードの配置)、`aria-sort`。
- red のアラートは `role="status"`(読み込み後の情報)、取得失敗は `role="alert"`。自動更新はないため、`aria-live` は更新結果の通知に使わない。
- 配色のコントラストは DS 2.1 の値(on-container 文字は 4.5:1 以上)。点線の枠は装飾ではなく状態を示すが、アイコンと文字でも伝える。

## 10. 検討した案

| 項目 | 検討した案 | 採用 | 理由 |
| --- | --- | --- | --- |
| シャードの配置 | マトリクス(cerebro 型)/ 一覧表 | マトリクス | 要件 0000 が cerebro のような UI を理想とする。配置の偏り・未割り当てが一目で分かる |
| 更新 | 手動のみ / 自動更新 | 手動のみ | 死活の監視は D1 の役割。O1 は調査用で、更新の失敗通知などを増やさない |
| システムインデックス | 常に表示 / 隠す切替 | 常に表示 | 切替は要件にない操作。OpenSearch 汎用の情報をそのまま出す(UC-8) |
| yellow の扱い | アラートを出す / カード内の説明のみ | 説明のみ | 単一ノードでは通常の状態で、毎回アラートを出すと、red の通知が埋もれる |
