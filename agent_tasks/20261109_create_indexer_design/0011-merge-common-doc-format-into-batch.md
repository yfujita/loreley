# 0011 indexer-api の 3.3「共通ドキュメント形式」を 4.3 に統合 作業記録

## ユーザー指示
「3.3 共通ドキュメント形式の存在意義がよくわからない。」→ 3.3 は4.3(バッチ登録)の `documents[]` 要素の定義にすぎず共通事項ではないため、4.3 へ統合する案を提示し、ユーザーが「修正して」と承認。

## 概要
document-writer が `indexer-api-v0.2.md` の 3.3 を削除し、項目表と補足3点を 4.3 のリクエスト内「`documents[]` の要素」表に統合した。共通事項を繰り上げ、文書内の章参照を直した。

- docs/v0.x/system-design/opensearch/schema/search-index-v0.2.md、loreley-texts-v0.2.md(同上の語の置換。49・53行、54行付近)

## 判断・設計上の理由
- 3.3 は4.3 だけが使う定義のため、リファレンス形式では4.3 のリクエスト表に置くのが自然。重複(`raw_content` の base64 の補足)は要素表に一本化。
- 「共通ドキュメント形式」という語は api 文書から消えるため、他文書の同語を 4.3 の `documents[]` への参照に置き換えた(用語の宙吊り防止)。
- 仕様・数値・ID・確認状況の区分は変更なし。SD への言及なし(grep で確認)。
