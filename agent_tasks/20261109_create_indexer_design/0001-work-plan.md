# 0001 作業プラン: Indexer 設計書と OpenSearch Schema 設計書の作成

状態: **承認待ち**(ユーザー未承認)

## 1. 目的とゴール

system-design-v0.8.md(以下 SD v0.8)から Indexer と Schema の範疇を抽出し、整理・改善して、各モジュールの設計書として独立させる。SD は最終的に破棄予定で、新文書が正になる。

受け入れ基準:
- 新文書だけで Indexer の責務・契約(API)・データ構造(Schema)が分かる。SD v0.8 を読む必要がない。
- 抽出対象に抜けがない。抽出マップ(SD の § と新文書の対応表)で全項目が追える。
- SD v0.8 内の食い違いは新文書側で解消し、解消内容を文書末尾の「変更点」か作業記録に残す。
- 数値・仕様・プロダクト判断は変えない。「案」「推測」「未決」は確定扱いにせず、各文書に確認状況(確定/案/未決)を明示する。
- document-reviewer の Critical / Important が解消している。task-reviewer が指摘なし、または Critical / Important 解消済みである。

仮の前提(Q1〜Q3 はユーザー未回答。推奨案を仮置き。異論があれば差し替える):
- **P1 Schema の範囲**: Indexer が書く3インデックス(検索インデックス、`loreley-texts`、`loreley-deletions`(仮名))をインデックスごとのファイルにする。`loreley-jobs` / `loreley-sources` は Crawler の領域として作らず、Indexer 文書では「読み取り/参照のみ」と書く。
- **P2 版の付け方**: 文書ごとに v0.1 から。v0.1 は SD v0.8 の忠実な抽出(旧 § 参照のみ修正)、v0.2 が改善版。版ごとに新ファイルを作り、前版は変更しない。
- **P3 改善の深さ**: 構造化と曖昧さの解消まで。仕様・数値は変えない。重複統合、経緯・変更点履歴の除去(単独で読める形)、案/推測/未決の一覧化、検索インデックスのマッピングを JSON で明文化(SD に決まっている方針の範囲内、未決は未決と明記)、API のリクエスト/レスポンス例の追加、数値の未決は未決一覧に集約。

- **P6 部分抽出**: §9(バックアップ)、§10(非機能)、§11(テスト設計)は Indexer 関連のみ抽出し、architecture 文書か Schema 文書の末尾に置く。テスト文書は別に立てない。
- **P7 ファイル名(案)**:

  - `docs/v0.x/system-design/indexer/indexer-api-v0.{1,2}.md`
