## 判断・設計上の理由
- 「SD に定めがない」は「未定義」「本書では未決」に、「SD が定める」は事実の直接記述(案なら(案))に言い換えた。確認状況の凡例は各文書が自分で定義(確定=ユーザー確定、案=ユーザー未確定、未決、推測=根拠が弱い想定)。
- SD 自身の状態を述べる行(「SD の整合確認は未完了」)は、言い換えると意味が変わるため3文書+api から削除。architecture G-9 は ID を保つため「全文の通読による整合確認は完了していない」に中立化して残した(不要なら削除可)。
- 削除した「変更点」章の内容(解消した食い違いの根拠)は経緯として以下に残す。
  - Status API の利用者は Crawler、Admin View は Admin API 経由(用語集の記述を従とした)。
  - 終了通知は「202 を返す。内容が異なる再送は 409(案)」に一本化。
  - 判定番号の二重は「割合ルールの判定1〜3」「削除判定の順1〜6」の呼び分けで解消。
  - Status API の 404 条件は「案。確定は未決」。
  - `deletion-{source_id}` の用途は推測の注記(開始通知の世代判定に使うように見える)。
  - Indexer が `loreley-jobs` を読む事実は architecture 2.3 の表に集約。
  - テスト D-18 欠番は引き継がない。
  - レビュー反映(0005・0006): K8/P25、K7/P16、ロック所有確認の文書ごと(案)と API-U-13、ソース削除ロックと API-U-14。
- 言い換えで補足した点: loreley-texts 第5章「手順は README に記載する予定」の「予定」は補足表現。
