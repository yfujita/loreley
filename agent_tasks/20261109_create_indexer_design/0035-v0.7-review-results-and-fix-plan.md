## レビュー指摘と対応方針
### Important
1. **K25 の判定基準の食い違い(b・a)**: architecture は「ダイジェストの記録の有無」、api 4.4 と loreley-deletions 2.2 は「`finish_received_at` または終端状態」。→ 3文書とも「ダイジェストが記録済みか」に統一。architecture 9.4 の `deletion_result` 項目にダイジェスト項目(項目名は未決。U-14)を追加、9.7 の受理時の行を「最初の終了通知が未受理(ダイジェスト未記録)の結果だけ」に。api 4.4 の「終端状態であることで再送を判定する」を削除、(1)の条件を「ダイジェストが未記録で、削除結果がすでに終端状態」に。
2. **「再送に 202 が返れば受理を確認できる」は誤り(a)**: 202 は分岐1(遅れた通知)・分岐2(未知の `crawl_id`)でも返る → 「202 は再送が冪等に処理されたことを示すだけ。受理の有無と削除の進行は Status API で確認する」に直す(9.5、12章、api 4.4)。受理を区別して返す案は U-4 に追記。
3. **K27 に G-10/G-11 を含める**: ユーザー確定。G-10/G-11 を欠番にして K27 に統合、4.3 の「導出」注記を K27 に。G-12 は導出・推測のまま。
4. **テスト観点(c)**: D-91 に追加((e) `failed`/`cancelled` の同内容再送→202、(f) `skipped_document_ids`/`oversize_document_ids` の順序違い・重複違いの再送→202、(g) 受理後に再起動し同内容→202・内容違い→409、分岐1 のあと内容違いの再送→202でダイジェスト未保存、`failed`/`cancelled` を受理した結果への `enumeration_completed` 再送)。E-45 にフィールド単位の確認(`summary`・`summary_model`・`text_hash` が無い、`last_seen_at`・メタデータ・`content_hash` は残る)と E-45b(要約生成中に抽出失敗へ遷移→書き戻しは破棄)、遷移後の再起動で再走査の対象外。S-9 を拡張するか S-13 を新設し、`last_seen_at` Update の負荷と要約書き戻しの負荷・競合を分け、指標・比較対象・規模条件を書く(閾値は置かず測定値の記録を合格条件)。16.1 の決定的再現の対象に C-7、D-40〜D-42、D-90、C-21(d)、D-88 を追加し、再現手段(フック、応答差し替え、直列キュー制御)を書く。
