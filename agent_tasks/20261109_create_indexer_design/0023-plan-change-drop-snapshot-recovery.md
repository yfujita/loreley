# 0023 プラン変更: スナップショット復旧を設計の対象外にする

## ユーザー指示(2026-11-10)
「復元は現段階では不要。もしインデックスが消えても再クロールで戻れば良い。スナップショットによるリカバリーは運用者が勝手にやればいいので今回の設計の中心にはおかない。」
F1(技術確認)の実行中に受けた指示。実行中だった tech-advisor はユーザー操作で停止されたため、スナップショット項目を除いて再依頼する。

## 0022 からの変更点
- 復旧の方針: インデックス喪失・破損時は**再クロールで戻す**(`last_seen_at` は初期化、要約は再生成)。スナップショットのリストアは設計の対象外。運用者の任意の運用であり、Indexer 設計書は仕様として定めない(禁止もしない。必要なら1行の注記にとどめる)。
- 復旧範囲の表(0022)は次に改める:
  - マッピング・アナライザ・辞書の変更 → `_reindex`(`_source` から再構築。再クロール不要)
  - インデックス喪失・破損、抽出ロジックの変更 → 再クロール
- 削除するもの: 14章のスナップショットの運用仕様、`_reindex` 前のスナップショット取得の必須化(旧インデックスの検証完了までの保持は、`_reindex` の安全手順として残すか writer が判断。必須としない)、リストア後の古さの扱い、スナップショットのテスト観点(R-5 の置換案)、U-13 の重要度引き上げ、PD での「スナップショット復旧」の受入基準追加。
- 引き渡し事項から「スナップショット運用」「スナップショット周期(U-13)」を外す。
- リスク(誤操作の影響大)は、「再クロールで戻せる(要約の再生成コストと再クロール時間がかかる)」として PD の主要リスクに記載する。
- F1 の確認事項から項目7(スナップショット/リストア)を除く。他は 0022 のとおり。

## ステータス
軽微な範囲縮小のため、プランの再承認は不要と判断(方針は同じ、スコープを減らす変更)。F1 を再依頼する。
