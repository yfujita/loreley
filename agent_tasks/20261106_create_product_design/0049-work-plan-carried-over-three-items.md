## 3. 案として置く事項(ユーザー未確定。SD では「案」と明記する)
- エラー応答: 400、エラーコード(例: `invalid_ratio_threshold`)、項目名、許容範囲。具体名は §12.5。
- 区分の名称: `confirmed` / `unconfirmed` / `unknown`。タイムアウト、接続エラー、5xx は `unconfirmed`。404 が続いたら `unknown`。保持件数Nの超過か `loreley-deletions` の喪失かは区別できないので「結果不明」に統一。
- 待ち時間の数値: §12.5 に回す。
- 登録結果の項目: 列挙件数、登録件数(新規・更新)、スキップ件数、原本サイズ超過件数、エラー件数。新規・更新の区別は Indexer のバッチ応答に含める(§12.5 の内部API契約に追記)。列挙の失敗、取り消し、Crawler の停止のときは、集計途中の値を「途中」と明示して保持する。原本サイズ超過件数とエラー件数の記録先は、PD #8 が未決のため項目だけ置く。保持はジョブ記録の保持に従う(Nとは別)。

## 4. 確認した事実とリスク
- Indexer の割合ルール(SD v0.7 §3.5 488〜491行): 「T が最小件数以下なら削除。そうでなければ T÷D ≤ しきい値なら削除」。T÷D は 1 以下なので、しきい値が 100%以上だと割合ルールが働かず全件削除になる。負の値は削除しない側(安全側)。欠損・NaN・数値以外は SD に定義がなく不定。D=0 の分母ゼロの扱いも SD に未記載。
- Q1・Q4 の回答により、Admin API を経由しない範囲外の値(特に 100%以上)では全件削除が起きうる。これを SD の受容事項(既知の制限)に明記する。欠損・数値以外・D=0 の挙動が SD 未定義である点も、既知の制限または §12.5 の未決として書く(新規の仕様は置かない)。
- Crawler の責務が増える(登録結果の集計と区分の記録)。Indexer のバッチ応答の形が内部API契約(§12.5)に波及する。
- #12 は #8(原本サイズ超過の記録先)と連動し、一部が未決のまま残る。
- `loreley-jobs` の項目が増える。案が増えるため、ユーザー確定と案の区別を崩さない。
- ロールバック: 新規ファイルを作るだけなので、v0.7 と v0.13 が残っていれば戻せる。
