## 指摘と対応
| 重要度 | 指摘 | 対応 |
|---|---|---|
| Important | 受容事項(9)(c)「D=0 は未定義」が §3.5 の判定順(手順1が先)と食い違う | D=0 は最小件数が0以上なら手順1で処理され除算しない。未定義なのは最小件数の欠損・負・NaN と、それが手順1に与える影響(§12.5 の未決)。最小件数・TTL も Admin API で検証しないと明記。D-55 を整合、D-70 を新設 |
| Important | Admin API を経由しない経路の漏れ | (9) に4経路(Crawlerの設定受付への直接入力、Indexerの開始通知への直接呼び出し、`loreley-sources` への直接書き込み・復元、v0.7 以前の保存値)を列挙。Crawler と Indexer の2経路は内部ネットワーク前提で受容(案)。更新時に値が省略された場合の扱いは未決 |
| Important | 登録結果の新規/更新と冪等な再送が矛盾 | 新規/更新は最初に成功した応答で数え、再送は数え直さない(案。内訳は目安に近い扱い)。§14.3 の「結果が変わらない」を「登録の状態が変わらない」に直した。E-38 新設 |
| Important | 「途中」が登録中の全体失敗を覆っていない | `failed`/`cancelled` で全バッチ完了前に終わった場合は理由を問わず `partial=true` のまま(案)。E-34 に (c) を追加 |
| Important | 区分の判定条件に未定義の分岐 | 優先規則(案): 404のみが連続すれば `unknown`、それ以外(混在を含む)は `unconfirmed`。連続回数で数える。ポーリング全体の上限時間が先に尽きたら `unconfirmed`。ポーリング中のCrawler停止・リース切れで回復 `failed` になった場合と、終了通知の失敗は区分なし(回復時に区分を書くかは未決)。D-63〜D-66 に分割・追加 |
| Important | 現在値の読み取り失敗(404以外)の表示が未定義 | 併記を省き、読み取り失敗を示す(案)。`unknown` で現在値が読めるのは後から復元された場合に限る。D-67、D-68 |
| Important | 「PD v0.13との既知の食い違いはない」(23行)が PD の古い文言を無視 | 仕様の食い違いはないが、PD v0.13 の文言(9.2 #9・#11、8.2)が古いので PD v0.14 で直す、と書き直した。#11 の待ち時間は本書でも未決 |
| Suggestion | 確定と案の混在(§3.5)、入力の単位 | NaN・数値以外の拒否、保存済みの設定を変えないことに「(案)」。入力の単位は §12.5 の未決 |
| Suggestion | 試験の追加・整理 | D-64〜D-70、E-38 を追加。D-52〜D-54 を「既知の制限の確認」に整理。`waiting_for` の併記は含める案(D-69) |
