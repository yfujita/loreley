## 設計への反映(案。document-writer への指示の中核)

- **割合を無視する削除モード**(以下「強制削除モード」)
  - クロールの起動時に指定する(起動要求のパラメータ。定期実行では指定できない=手動実行のみ、とする案)。開始通知で Indexer に渡す。
  - 割合ルールと最小件数ルールだけを無視する。次の安全条件は無視しない:列挙が最後まで完了していること、世代が現行であること、件数照合(`enumerated_count == N_seen + E_missing`)が成立すること、メンテナンスフラグが立っていないこと、スキップ文書の除外。
  - 0件列挙でも、強制削除モードなら全件削除する(これが全ファイル削除の経路)。
  - 同期結果に、強制削除モードで実行したことを記録する。
- **割合の設定**:データソース(クロール)の設定に、削除率の閾値(既定値は未決。v0.9 §9.1 の持ち越し)を持たせる。開始通知の設定スナップショット(A5)で Indexer に渡す。
- **Status API**:`GET /syncs/{crawl_id}`。状態(`running`/`deleted`/`skipped_by_ratio`/`validation_failed`/`discarded`/`interrupted`/`failed`)、対象件数、分母、削除件数、強制削除モードの有無を返す。Crawler がポーリングする。ポーリングの間隔・上限時間は §12.5 の数値。
- 0025 のとおり、承認(保留・承認・却下)は廃止。0件列挙の保護は「割合ルールで削除しない」で働く。
