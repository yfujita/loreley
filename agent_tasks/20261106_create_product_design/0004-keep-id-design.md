# 0004 ID設計の再検討（現状維持）

## 実施した作業の概要

ユーザーから、`source_id`と`external_id`を廃止する案が出た（2026-11-06）。`document_id`を一意にするだけでよく、違うConnectorで取得した同じ文書は同じIDにしてよい、という案である。この案の影響を整理してユーザーに伝えたところ、ユーザーは現状のID設計を維持すると判断した。

## 変更したファイル

なし。v0.2の§3.1.1、§3.1.2、§3.3はそのまま残した。

## 判断・設計上の理由（現状を維持した理由）

違うConnectorで取得した同じ文書を同じIDにするには、ID生成で次のどちらかを選ぶ必要がある。どちらにも問題がある。

- 本文のハッシュをIDにする：文書を更新するとIDが変わり、Agentが持っている古いIDが無効になる。
- URLやパスのハッシュをIDにする：取得経路が違うとURLやパスも違うことが多く、同じIDにならない。

さらに`source_id`をなくすと、次の機能が成り立たなくなる。

- データソースによる絞り込み（`source_ids`）と`list_sources`
- データソースごとの件数表示
- 削除判定（別の経路にまだ残っている文書を消さないための判定）

## 未対応事項・次にやること
