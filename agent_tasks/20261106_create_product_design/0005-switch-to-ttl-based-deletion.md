# 0005 削除方式を期限による削除に変更

## 実施した作業の概要

ユーザーから削除方式を見直す案が出た（2026-11-06）。クロール時に文書へ期限を入れておき、クロールが完了したときに期限を過ぎた文書を一律に削除する、という案である。この案の論点を整理してユーザーに伝え、ユーザーは次のように判断した。

- 論理削除（`deleted`フラグ）と猶予期間をやめ、期限による削除に一本化する。
- 期限は`last_seen_at`（クロールで最後に見つかった日時）で表す。`expire_date`は使わない。
- `last_seen_at`は検索インデックスの本文ドキュメントに持たせる。Store層の別インデックスには置かない。

この判断をもとに、document-writerでv0.2に反映した。

## 判断・設計上の理由

- 期限による削除にすると、論理削除の状態と猶予期間を別々に管理しなくて済む。TTLがそのまま猶予期間の役割を果たす。
- `expire_date`ではなく`last_seen_at`にした。TTLの設定を変えたとき、次のクロールを待たずに反映されるためである。
- 削除は、全件を列挙するクロールが正常に完了したときだけ行う。対象は同じ`source_id`の文書に限る。この2つの条件で、取得の失敗による誤削除と、他のデータソースの文書の誤削除を防ぐ。
- 削除率のしきい値による保留と承認は残した。
- 検索時に`last_seen_at`で除外はしない。クロールが失敗し続けると、全文書が検索から消えてしまうためである。
- 毎回すべての文書を部分更新するので、文書全体の再書き込みが発生する。このトレードオフは、ユーザーが本文ドキュメントに持たせると判断した。負荷は実装後に実測する（§8.2）。
