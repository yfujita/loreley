## 反映内容

- 同期結果→クロール結果(登録結果・削除結果に分ける)、同期状態→クロール状態、最終同期時刻→最終クロール完了日時、同期管理→Indexerの削除処理。責務表・構成図注記・§4.6・§4.7・§5.2・§9.2 #11・用語集を整合。
- Indexer を「文書の登録・更新・削除を担当するコンポーネント」と定義。
- §4.7: ジョブは文書の取得・登録とIndexerの削除処理が完了した時点で終了。割合ルールで削除見送りも正常終了。Crawler処理完了とジョブ完了を区別。確認のタイムアウト時は警告のみで成否は変えない。削除の中断は削除結果に残し、残りは次のクロールに委ねる(SD §3.9 `interrupted` と一致)。
- 用語集末尾に「旧用語との対応」小節を追加。改訂履歴から参照。
- 誤削除リスク行の削除条件を「列挙完了+Indexerでの検証(世代・件数照合)を通ったとき」に修正(SD §3.9 に合わせた)。
- §9.2 #12 を追加: 登録結果の保持場所・項目(SD の Status API に追加するか)は SD で決める。
- 対象外として「ACL同期」「非同期」は残した。
