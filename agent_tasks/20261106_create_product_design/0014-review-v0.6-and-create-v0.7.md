# 0014 プロダクトデザインv0.6のレビュー反映とv0.7作成

## 実施した作業の概要

ユーザー指示「v0.6のレビュー指摘を確認し、修正点があれば修正してv0.7を作成して」に基づき、document-writer で v0.7 を作成した。個別のプラン承認は取っていない(0010〜0013 と同じ扱い)。

反映した指摘:
- ①(高): 9.1 最小件数ルールの説明の逆転を修正。採用すると少数の削除は率が高くても保留されない。採用しないと、少数の文書のソースで通常の削除まで保留され得る。判断自体は承認待ちのまま。
- ②(高): 2章「Admin Viewを保護しない」の「再インデックスを実行できる」を「クロールの手動実行やジョブの再実行ができる」に変更(4.6で再インデックスは手動手順のため)。
- ③(高): 読めない文書への対処を「アクセス権の修正、データソース設定の除外条件による取得対象からの除外など、失敗原因を解消して再実行する」に統一(2章、4.6、9.1)。新しい除外管理機能は作っていない。
- ④: 8.2を「更新は次回クロールで反映。削除はTTL経過後の、列挙クロール正常完了時に反映」に分離。
- ⑤: 1.4に、MVPの完成基準は「測定できたか」であり、品質目標はGA条件(8.5)で定める旨を追記。
- 2章の提案: 9.1「システムデザインに移した仮決定」表と9.2「システムデザインに移したもの」節を削除(履歴はGit)。

## 判断・設計上の理由

- 読めない文書の除外は、system-design §2.1 の `loreley-sources` に除外条件が既にあるため、新機能にせず既存設定の範囲とした。
- §3.7(恒久失敗の将来拡張)と、§3.5 の Store層だけにある文書の手動削除(別の論点)は変えていない。
- 9.1 / 9.2 の移行履歴は、プロダクトデザインの責務外のため削除した。他章・system-design に参照は残っていない。
