# 0038 作業プラン: SD v0.6 の作成(「同期」の用語を外す)

## 背景

ユーザー指示(2026-11-08)「SDも改訂して」。0036・0037 で PD v0.11 から「同期」を外した。SD v0.5 には「同期」124件、`loreley-sync` 45件、`Sync Manager` 23件、`/syncs/*` API、§3.9「同期管理(Sync Manager)」がある。PD と用語をそろえる。

## 方針

- `system-design-v0.5.md` は変更せず、`system-design-v0.6.md` を新規作成する(SD は版を分けるルール)。対応 PD は v0.11 のまま。
- 用語・識別子の置換のみ。仕様は変えない。
- Indexer は「同期を管理するサービス」ではなく、文書の登録・更新・削除を担当するサービスと書く。

## 置換方針

| v0.5 | v0.6 |
| --- | --- |
| 同期結果 | 削除結果(Status APIの項目は現状削除側のみ。登録結果の項目追加は未決として §12.5 に追加。PD §9.2 #12 に対応) |
| 同期状態(Crawler) | クロール状態 |
| 同期管理(§3.9) / Sync Manager | 削除管理(Deletion Manager) |
| 最終同期時刻 | 最終クロール完了日時(`list_sources` の最終クロール時刻との対応を明記) |
| `loreley-sync` | **要決定(下記)** |
| `/syncs/start`、`/syncs/{crawl_id}`、`/syncs/{crawl_id}/finish` | **要決定(下記)** |
| 同期の通知・同期の記録・同期のたびに など | 文脈ごとに「削除処理」「クロール」へ |

対象外: 「非同期」(要約の非同期生成、§8.2 ほか)、「ACL同期」。

## 要決定(推奨案つき)

識別子(インデックス名・API パス・内部名)は実装契約になる。まだ実装前なので**改名を推奨**する。

- 推奨: `loreley-sync` → `loreley-deletions`、`/syncs/*` → `/crawls/start`、`/crawls/{crawl_id}`、`/crawls/{crawl_id}/finish`、`syncresult` → `deletion_result`。
- 代替: 識別子は据え置き、本文の用語だけ置換する(識別子と用語が食い違うが、改名の影響は出ない)。

## フェーズ

1. **作成**(document-writer): v0.5 のコピーから v0.6 を作る。置換表に従い全章を置換し、§3.9 の見出しと節の説明を改める。冒頭に変更点要約・旧用語との対応表、改訂履歴を足す。PD v0.11 の用語集・§9.2 #12 と整合させる。
2. **レビュー**(document-reviewer): 置換漏れ・誤置換(非同期・ACL同期)、仕様の意味の変化、識別子の全章での一貫性(§3.9、§4、§7、§11 の試験名など)、PD との整合を確認する。
3. **タスクレビュー**(task-reviewer)。
4. **作業記録**(メイン): 0039 に結果を記録する。

- 既存の持ち越し(原本サイズ超過時の既存索引の扱いなど)は本版では扱わない。
- 作成後も v0.5 は残す。コミットはユーザー指示待ち。
