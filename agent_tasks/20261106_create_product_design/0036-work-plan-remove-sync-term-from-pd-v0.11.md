# 0036 作業プラン: PD v0.11 から「同期」の用語を外す

## 背景

ユーザー指示(2026-11-08)。実際の処理は「Crawlerが文書を列挙・取得 → Indexerが登録・更新 → クロール完了後にIndexerが古い文書を削除」だけである。TTL・割合ルールがあるため、データソースと索引は完全には一致しない。「同期」と呼ぶと状態を一致させる独立した仕組みがあるように見えるため、用語をやめる。Indexer は「同期を管理するサービス」ではなく、文書の登録・更新・削除を担当するサービスと定義する。

## ユーザー決定

- 反映先: **PD v0.11 を直接修正**(版は増やさない。改訂履歴に1行追記)。
- SD: **今回は無変更**。次の SD 改版で置換する。

## 置換方針

| 現在の用語 | 変更後 |
| --- | --- |
| 同期結果 | クロール結果。API・内部データでは「登録結果」「削除結果」を分けて持つ(Indexerの処理結果を含むか曖昧になるため) |
| 同期状態(Crawler) | クロール状態 |
| 最終同期時刻 | 最終クロール完了日時 |
| 同期処理の完了 | 登録・削除処理の完了 |
| Indexer の同期管理 / Sync Manager | Indexer の削除処理(Deletion Manager など) |
| 同期結果を確定する | 登録・削除の処理結果を記録する |
| 用語集「同期(同期結果)」 | 削除し、「クロール結果」「登録結果」「削除結果」に置き換える |

§4.7 の記述は次のとおり変更する。

> クロールジョブは、文書の取得・登録と、Indexerによる削除処理が完了した時点で終了する。削除割合ルールにより削除が見送られた場合も、正常終了として扱う。

Crawlerの処理完了とクロールジョブ全体の完了は区別して書く。

## 対象外(置換しない)

- 「ACL同期」(将来の権限連携。別概念)
- 「非同期」(要約の非同期生成。別概念)
