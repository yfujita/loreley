## 反映内容

- ① 4.7/9.2 #11: 原則は終端状態までジョブは完了しない。確認に待ち時間の上限を設け、超過・取得不能(接続エラー・5xx・404 継続)のときは警告を残してジョブを終える(成否は変えない)。削除結果は「結果未確認」、404 継続は「結果不明」として Admin View で確認できる。ジョブを実行中のまま保持し続ける案(レビュー提案)は採らず、SD §3.9(警告のみ・ロック解放)に合わせた。再確認の有無・待ち時間・知らせ方は SD で決める。
- ② 4.7/8.1: 新しいクロールの開始による中断は、通常の直列実行では起きない。起きるのは確認タイムアウト後・取り消し後・ロックの強制解放後など。
- ③ 4.6/5.2/8.2/9.1/9.2/用語集: しきい値は 0%以上 100%未満。100% では全件削除を防げないため。全件削除は強制削除を使う。0% は最小件数を超える削除を自動では実行しない設定。
- 細部: 改訂履歴 v0.11 の SD 置換の記述を過去形に、4.2 の SD 参照を v0.6 に、9.2 #12 に登録結果の最低限の項目(列挙・登録(新規/更新)・スキップ・原本サイズ超過・エラー件数)を追加。
- レビュー反映: 「結果未確認/不明」が SD 未反映である旨を 9.2 #11 に明記、未確認後の最新状態が中断・破棄の場合もある旨、9.1 に v0.12 の根拠を追記。

## 判断・設計上の理由

- 「結果未確認/結果不明」は PD 側の新しい決定。ユーザーのレビュー意図(タイムアウト時に正常終了と決めつけない)を満たしつつ、SD と矛盾しない形にした。
- レビューの提案「軽微な表現改善より重大な矛盾に絞る」に従い、追記は矛盾解消に必要な範囲にとどめた。
