# 0006 ハイライト用にオフセットを保存する方針に変更

## 実施した作業の概要

ユーザーから指摘があった（2026-11-06）。OpenSearchではterm offsetsを保存すれば、ハイライト時の再解析を避けられる。したがって、`index.highlight.max_analyzed_offset`があるというだけで、長文全体の索引化を諦める必要はない、という指摘である。

v0.2の§3.3.2は、この上限を超えないように本文サイズの上限を決める書き方になっていた。この記述を直した。変更は数行なので、メインエージェントが直接編集した。

## 変更したファイル

- `docs/product-design/product-design-v0.2.md` §3.3.2
  - ハイライトに使うフィールドは、`index_options: offsets`でオフセットを保存してマッピングする。n-gramなどのサブフィールドも対象に含める。
  - こうすると再解析が起きず、`max_analyzed_offset`は適用されない。そのため、この上限を理由に本文を切り詰めない。
  - オフセットの保存でインデックスサイズが増える。増え方は実装時に計測する。
  - 本文サイズの上限（§3.2.1）は、ハイライトとは別の観点（リクエストサイズ・インデックスサイズ・処理時間）で決める。

## 判断・設計上の理由

- unifiedハイライタ（既定のハイライタ）は、ポスティングにオフセットがあればそれを使い、本文を再解析しない。`max_analyzed_offset`が効くのは再解析するときだけである。
- 一方で、本文サイズの上限そのものは残した。リクエストサイズの上限、インデックスの肥大化、抽出や要約の処理時間など、ハイライト以外にも上限が要る理由があるためである。

## レビュー

- 文書レビューはまだ行っていない。タスク全体のレビュー（task-reviewer）で併せて確認する。
- OpenSearchの公式ドキュメントで、オフセットを保存したフィールドに`max_analyzed_offset`が適用されないことを、実装時に確認する。

## 未対応事項・次にやること
