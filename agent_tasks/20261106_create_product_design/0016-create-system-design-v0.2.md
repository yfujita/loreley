## 概要
0015 の未対応事項に対応し、`system-design-v0.2.md` を作成した(v0.1 は変更していない)。ユーザー指示は「続けて」。
レビュー(general-purpose)の指摘11点を反映し、`product-design-v0.8.md` も補正した。実施は document-writer、レビューは general-purpose。

## 変更ファイル
- 新規: `docs/v0.x/system-design/system-design-v0.2.md`
- 修正: `docs/v0.x/product-design/product-design-v0.8.md`(新規作成版のその場修正)
  - 関連文書リンクを v0.2 に更新。
  - スキップの定義から「抽出」を外した。抽出失敗は従来どおり `extract_failed` で登録し、スキップ件数に数えない。
  - 「列挙クロールの正常完了時のみ削除」を「列挙が最後まで完了したときのみ削除」に統一(L90、5.2、8.2、用語集)。
  - 「一定回数リトライ」を「数回リトライ」に統一。

## v0.2 の主な設計
- **スキップ**: 最大3回試行、指数バックオフ(初回1秒、2倍、上限30秒、ジッタあり)。値は案で、設定可能。
- **スキップ記録**: `loreley-jobs` に保存する。Admin View に一覧を出す。成功、文書削除、ソース削除、次回の列挙で見つからなかった場合に消す。
- **誤削除防止**:
  - `last_seen_at` を、列挙で見つかった時点で全文書に部分更新する(MVPに取り込み)。
  - 削除フェーズで、今回のスキップ文書を明示的に除外する(二重防御)。
- **ジョブの状態**: スキップのみなら `partially_succeeded` でも削除を行う。
- **failed(削除しない)にするもの**:
  - 列挙中のエラー(ディレクトリのアクセス不可を含む)。
  - 部分更新の失敗。
  - OpenSearch 全体の異常(接続、タイムアウト、429、5xx、`cluster_block_exception`、circuit breaker)。
  - 文書固有の 4xx 拒否が連続20件。
- **テスト**: E-2、E-3、E-7 を更新。E-19〜E-26 と D-10 を追加。

## 判断理由
- 部分更新の失敗を `failed` にしたのは、`last_seen_at` が更新されないと、読めない文書が TTL 後に誤削除されうるため。
- 抽出失敗をスキップに含めないのは、リトライで直らず、`extract_failed` でもタイトルとメタデータが検索できるため。v0.8 側をシステムデザインに合わせた。
