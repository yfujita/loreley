# 0015 読めない文書のスキップ方針への変更(v0.8 作成)

## 概要
ユーザー指示(2026-11-08):「読めない文書による削除の停止について、読めない文書があった場合は数回リトライしてスキップする。その他の処理に影響させない。」
v0.7 の「失敗した文書が1件でもあると、そのソースの削除が止まり続ける」を廃止し、`product-design-v0.8.md` を作成した(v0.7 は変更していない)。
プランの作り直しは行わず、軽微な追加指示として直接対応した(ワークフローの「途中の追加指示」)。ただし、削除の仕様に関わる変更なので、内容はユーザーの確認を待つ。

## 実施内容(document-writer 実施、レビューは general-purpose)
- 読めない文書は数回リトライし、失敗したらその文書だけスキップする。クロール全体・他文書の登録・削除判定には影響させない。
- スキップがあっても、列挙が正常に完了していれば削除は行う。
- 誤削除防止: スキップした文書も、列挙で見つかった時点で最後に見つかった日時(`last_seen_at`)を更新する。読めないだけでは TTL で削除されない。
- クロール全体の異常(列挙失敗・0件列挙・マウント外れ)では従来どおり削除しない。
- スキップした文書は Admin View で確認できる。
- 恒久失敗の判定は不要になったので、将来拡張から外した。

## 変更ファイル

  - 版履歴、1.4、2章(制限事項・誤削除の行)、4.1、4.6、5.1、5.2、8.2、8.4、決定事項表、用語集

## 判断理由
- `last_seen_at` 更新方式を選んだ理由は、system-design §3.7 の「発見と取得の分離」および §1.1(`last_seen_at` は列挙で見つかった日時)と一致するため。クロール間をまたぐ保護にもなる。

## レビュー結果(general-purpose)
- v0.8 本文は指示を一貫して反映している。旧挙動の取り残しはない。範囲外の変更もない。
- 重大: MVP の system-design は `last_seen_at` の部分更新を行わない(SD L77, L197)。このままでは、スキップした既存文書が TTL 後に誤削除される。システムデザイン側の修正が必要。
- 軽微: 「数回リトライ」と「一定回数リトライ」(5章のジョブ)の表現のゆれ。未修正。
