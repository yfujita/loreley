## 反映する大方針

0017 でユーザーが確認済みの内容のうち、方針レベルのものだけを設計書に書く。

1. メッセージブローカーは使わず、コンポーネント間はHTTPで直接通信する。
2. Crawler と Indexer は別コンテナ。ジョブの起動もHTTP(Crawler が受信時にジョブとロックを記録し、受け付けたら非同期で実行する)。
3. 責務:ジョブ・ロック・リース・スキップ判断は Crawler、検索インデックスと `loreley-texts` への書き込み・要約生成は Indexer。書き込み前のロック所有確認は Indexer。
4. Crawler → Indexer は、同期HTTPのバッチ登録。完了を確認しながら進める(削除の安全性との相性)。大きな原本には上限を設ける。
5. 契約を明確にしておき、将来キューが必要になれば、HTTP部分をメッセージングに置き換えられるようにする。
6. 内部通信は内部ネットワークのみ。`:ro` マウントは Crawler のみ。単一ホスト・単一インスタンス・直列実行は維持する。

## 書かないこと(後続に回す)

- endpoint の一覧、リクエスト/レスポンス形式、エラー種別。
- 数値(バッチ件数・サイズ上限、タイムアウト、リトライ回数の変更)。
- 新規テストケースの設計。影響を受ける既存テストの ID の列挙にとどめる。
- 0017 の「前提として置く案」のうち、細部のもの(`seen` API の形、503 `maintenance` の扱いなど)は、設計書では「方針:実装時に決める」と書く。
