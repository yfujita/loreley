# 0019 作業プラン更新:`loreley-texts` の廃止を別の版に分ける

> 状態:**ユーザー承認待ち**。0018 のプランに、`loreley-texts` 廃止を後続の版として追加する(0018 は書き換えない)。

## 背景

ユーザー指示(2026-11-08):「`loreley-texts` はいらない気がする」→ 分析を提示 → 「分ける方をお願い」。
`loreley-texts` の廃止は §1、§2、§3、§8、§11 の広範囲に及ぶため、コンテナ分離(v0.3)と同じ版に混ぜず、別の版にする。

## 版の分け方

| 版 | 内容 |
| --- | --- |
| system-design v0.3 / product-design v0.9 | 0018 のとおり(Crawler / Indexer のコンテナ分離とHTTP直接通信)。`loreley-texts` は**残す**。ただし「Indexer が `loreley-texts` と検索インデックスの唯一の書き込み役」という責務は書く |
| system-design v0.4 / product-design v0.10(必要なら) | `loreley-texts` を廃止する。文書の本文・要約・処理状態は検索インデックスに一本化する。`loreley-jobs`(設定・ジョブ・ロック)は残す |

v0.4 以降のフェーズ詳細は、v0.3 完了後に別のプランとして出す。

## v0.4 で扱う論点(分析の要約。着手時に改めて確認する)

- 外す理由:検索インデックスに `text` を既に持つ。差分検知がMVPから外れ(0011)、毎回全文upsertなので `pending_*` による状態管理の価値が薄い。再インデックスは `_reindex` で `_source` から行える。
- 失うもの:「正と派生物」の分離。検索インデックスが壊れた場合は再クロールが必要。
- 移すもの:要約の状態、スキップ記録、`extract_failed` の表現。
- 影響範囲:§1.5、§2.4、§2.5、§3.8、§8、§11、product-design のStore層の記述。
- **v0.4 着手前に、廃止の方針をユーザーが最終確認する**(今回は「分ける」ことのみ確定)。
