## 指摘と判断

外部レビュー(PR #19、High 1・Medium 3)の 4 件を、コードを読んで確認した。いずれも指摘のとおりだった。

| # | 指摘 | 確認結果 | 対応 |
| --- | --- | --- | --- |
| 1-1 | テストの接続先 URL が固定されていない(シェルに残った `LORELEY_IT_*_URL` が別環境に向く) | `support.py` は環境変数を読み、スクリプトはポートと索引名しか固定していなかった | スクリプトが `LORELEY_IT_{OPENSEARCH,INDEXER,CRAWLER,API}_URL` を 127.0.0.1 の固定ポートに export。pytest 直接実行時のみ上書き可 |
| 1-2 | 事前確認と起動の間の競合(同時実行の排他がない) | 事前確認は排他ではない。ただし 3 本のスクリプトに共通する既存の方針 | **今回は対応しない**。3 スクリプト共通の排他ロック(`mkdir` 方式など)は別タスク(レビューも別タスク可としている) |
| 1-3 | `docker ps -a` の失敗と `ls -A` の失敗を「残骸なし」と扱う | `\|\| return 1` の文脈では `set -e` が効かず、空の出力と区別できなかった | `docker ps` の失敗で中止。`data/` は存在確認と一覧取得を分け、一覧を取れなければ中止(安全側) |
| 1-4 | テスト成功でも後始末に失敗すると終了コード 0 | `cleanup()` が pytest の終了コードをそのまま返していた | テスト成功かつ後始末失敗のとき終了コード 11(`EXIT_CLEANUP_FAILED`)。テスト失敗時は pytest の終了コードを維持 |

## 検証

- 1-3: 偽の `docker`(PATH 先頭)で `docker ps` を失敗させて、終了コード 1 で何も消さず中止することを確認。`data/` を `chmod 000` にして、終了コード 1 で中止することを確認(のち復元・削除)
- 1-4: 偽の `docker` で `compose down` を失敗させ、`-k test_01`(5 件成功)で、終了コード 11・`data/` を削除しない案内が出ることを確認。残ったスタックは手動で `down -v` し、`data/` も削除した
- 1-1: 同じ実行で `LORELEY_IT_API_URL`・`LORELEY_IT_OPENSEARCH_URL` に `http://127.0.0.1:9999` を設定してから実行し、スクリプトに上書きされてテストが成功することを確認
- 全体: 修正後のスクリプトで通常実行し、23 件成功(449.58 秒)、終了コード 0。実行後にコンテナ・ボリューム・`data/` の残骸なし(他プロジェクトの `opensearch-opensearch-1` は未操作)
- 未実施: shellcheck(未導入)。`bash -n` のみ
