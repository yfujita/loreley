## 設計内容(案)

- 条件: インデックス名(部分一致・大文字小文字は区別しない・文字列一致で正規表現ではない・trim 後に空は条件なし)+状態(green/yellow/red の複数選択。名前と状態は AND。3 つとも選択=条件なしに正規化。未知の状態値のインデックスは、状態を選ぶと除外し、何も選ばないときだけ表示)。システムインデックスだけを対象にする絞り込み・切替は追加しない(#22 の「区別しない」方針と、要件にない条件の追加になるため。名前の一部一致では「`.` で始まる」だけを抽出できないが MVP では許容)。ノード・シャード数・件数範囲などは追加しない(拡張点として 10 章・8.3.1 に記載)
- 絞り込みは画面側(Admin API は全件返し。API 変更なし。数千件超の規模でのサーバー側絞り込みは後続設計)。読み取り専用のまま
- 置き場所: カード「クラスタ状態」の、概況の下・マトリクス領域の上(`role="search"`、状態は `fieldset`+`legend`)。概況は絞り込みの対象外(クラスタ全体のまま)。境界線は概況の下とフォームの下の 2 本
- 適用: 名前は 250ms debounce(IME 変換中は開始せず確定後)、Enter ですぐ、状態はチェックの切替ですぐ。直前に適用した条件と同じなら何もしない(ページを保つ)。「条件を解除」ボタン(条件なしは `aria-disabled`。押すと名前欄にフォーカス)。条件を変えると 1 ページ目に戻る
- URL(案): `?q=logs&state=yellow,green`(`router.replace`。ページ位置は入れない)。route の行にもクエリを記載(J1・X1 の流儀)
- 件数表示(`role="status"` `aria-live="polite"` `data-testid="o1-count"`): 「a–b / 絞り込み後 N 件のインデックス(全 M 件中)」(N=絞り込み後、M=全件に全文書・モックで統一。「(全 M 件中)」は折り返さない)。ライブリージョンは常に DOM に残す
- マトリクス: ノード行の「シャード n」・未割り当て行・凡例は絞り込み後(全ページ)のデータで判定。補足に適用中の条件と「概況はクラスタ全体の値で、絞り込みの対象外」。一致 0 件は、件数表示に「絞り込み後 0 件のインデックス(全 M 件中)」+空ブロック「条件に合うインデックスがありません」(ブロック内に解除ボタンは置かない。フォームの 1 つだけ)。補足は「適用中の条件」の文だけ。凡例・ページ送りのボタン・表は出さない
- 各状態のフォーム: インデックス 0 件・エラーは出さない、読み込み中は無効(URL から復元した条件値を表示。入力欄も無効の見た目。DS 4.6 に無効入力の規定を追加)、stale は使える
- フォームの高さ(モック・macOS システムフォント・1 回の実測): 1145px 以上 86px(1 行)、1024px・768px 126px、840px 151px、375px 219px(状態チェック 3 つ 1 行)、320px 263px(2 行+1 行に折り返し)。600px 未満のタップ領域 44px。列数の式・列幅・並び順は変更なし

## 縦の増加について(要確認の実測)

designer が当初「過大でない」と書いていた記述は、実測で成り立たなかったため改めた。1280px は表の上端がページ上端から約 540px で 1 画面に入る。**375px は約 970px(フォームがなければ約 750px)、320px は約 1030px で、フォームにより最初の 1 画面の外に出る**。DS の前提はデスクトップ優先(1280px 基準)のため許容を推奨。許容しない場合の案は、狭い幅でフォームを折りたたみ式にすること(後続設計)

- web-ui-reviewer: Critical・Important なし。16 状態×7 幅(320〜1280px)で横スクロール 0。実操作(debounce、Enter、Space、AND、解除、ページ送り連動、0 件、大文字小文字、正規表現文字)・8 つの条件の全ページ走査で、ノード行・未割り当て行の「シャード n」とチップ合計が全一致、凡例の出し分け・概況の不変を確認。Suggestion 1(6 章の「状態のチェックは 3 つ 1 行」が 320px の実測と食い違い)・Nitpick 5(件数表示の句の途中の折り返し、条件が変わらない Enter でページが戻る、読み込み中の入力欄の見た目、0 件の補足、1024px の記載)→ 反映
- document-reviewer: **Critical 1**(未割り当て行の補足「シャード n」が 3.3「全インデックスの合計」と 3.5「絞り込み後の合計」で矛盾)・Important 8(旧記述の取り残し 2、DS 4.12 の「変種」の書き方、0 件の状態の規則、システムインデックスの根拠の誤り、承認区分の不備 3、route のクエリ、状態フィルタのエッジケース)・Suggestion・Nitpick → 反映。「迷うので追加しない」・searchbox の記述は削除済み(grep 0 件)

## ユーザー確認が必要な点(PRレビュー)

1. 条件の種類(推奨: 名前+状態の 2 つだけ。システムインデックスだけを対象にする条件は追加していない)
2. 狭い幅(375px・320px)でフォームにより表の上端が最初の 1 画面の外に出ること(推奨: 許容。許容しない場合は狭い幅でフォームを折りたたみ式にする後続設計)
3. 状態を 3 つとも選んだときは「すべて」と同じ扱い(推奨)
4. 行見出し・凡例・未割り当て行を絞り込み後にそろえること、URL に `q`・`state` を入れてページ位置は入れないこと(推奨)
