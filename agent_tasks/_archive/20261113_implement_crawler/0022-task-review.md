## 3. 設計書の改版依頼リストへの追加(提案。0021 §5 に追加)

1. architecture 3.2・7.x(Store 層): 全体異常を「結果区分として返す」のでなく例外 `StoreUnavailableError`(理由名つき)として伝播させる(0006 §4-2)。想定外の4xx は `StoreUnexpectedResponseError`(`failed(internal_error)`)
2. architecture 3.1・6.x: `list_records` は検索の前に refresh する(走査・条件指定削除の契約にだけ refresh を明記していたため補った。0006 §4-5)
3. architecture 3.2: 記録なしの版条件つき書き込み(置き換え・削除)は `Conflict`(実 OpenSearch 3.9.0 で確認。0006 §4-3・0007 §4-4)。`NotFound` は版条件なしの取得・走査の結果区分
4. crawler-api 4.4: `ttl`・`min_delete_count`・`schedule_interval_seconds` が int64 の範囲外のときの扱い(設計書は範囲を検証しない=400ではなく500や Indexer 側の400になりうる)。`api` で型として表現可能な範囲だけ `format` で弾くかを決める(0012 §1・§5-8)
