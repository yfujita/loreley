## ユーザー確定済みの回答(2026-11-21、いずれも推奨案を選択)

- **Q1 OpenSearch ダッシュボード**: Admin View に読み取り専用の最小ビュー(クラスタ状態・インデックス一覧・ドキュメント件数・シャード配置)を自前で持ち、MVP に含める。PD §4.6 の「OpenSearch Dashboards への導線(任意)」は残す。PD v0.19 への追加として機能設計書に明記し、PD 追従改訂が必要である旨も記載する。
- **Q2 Crawler の起動/停止/実行状態**: 起動=手動クロール起動(`force_delete` 指定可)、停止=実行中ジョブの取消、実行状態=ジョブ状態・登録結果・削除結果の参照。Crawler コンテナ/プロセスの起動停止・再起動は対象外。定期実行の有効/無効切替の専用機能は設けない(`schedule_cron` を null にすることで代替)。
- **Q3 Loreley ダッシュボード**: 死活表示のみ(crawler / indexer / opensearch / api・web)。任意コンテナ(opensearch-dashboards / embedding / llm)は設定されている場合のみ表示。取得経路は機能設計書では決めず後続のシステム設計に回す。SD v0.8 §7.3「api は indexer に接続しない」制約と、Crawler/Indexer の `/healthz` が Admin API 契約外(crawler-api-v0.4 §1。CAPI-K-9 / CAPI-P-19)である点を未解決事項として明記する。

## MVP に含める Admin View 機能(PD v0.19 §4.6 / §4.7 / §8.2 の決定済み + 上記回答)

1. データソース設定の管理(データソース・`schedule_cron`・TTL・削除の割合ルールのしきい値(0%以上100%未満)・最小件数。登録・更新。更新は Admin API が検証)
2. 手動クロール起動(`force_delete` は手動実行のみ指定可)、実行中ジョブの取消、失敗ジョブの再実行
3. ジョブ状態の参照(状態・エラー・最終クロール完了日時。登録結果:列挙件数・登録件数(新規・更新)・スキップ件数・原本サイズ超過件数・エラー件数。削除結果:削除件数と割合ルールで削除しなかった理由・件数。「結果未確認」「結果不明」を `loreley-deletions` の現在値と併記。承認・却下の操作なし。メール通知は MVP 対象外)
4. 文書単位の確認ビュー(データソースごと): スキップ文書(external_id、stage、reason、attempts、consecutive_skips、first/last_skipped_at、既存/新規、直近ジョブへのリンク)、抽出失敗(`extract_failed`)、原本サイズ超過
5. インデックス件数の確認(PD §4.6)
6. OpenSearch 最小ビュー(Q1)
7. Loreley ダッシュボード(死活表示のみ。Q3)

## 前提として置いた事項(ユーザー未確認。★はレビュー時にユーザー確認を要する)

- 409 重複起動の表示: 拒否理由 3 種(`lock_held` / `maintenance_enabled` / `source_deleting`)ごとに表示し分ける(CAPI-P-4)。`lock_held` では既存ジョブ(`details.existing_job`)を案内し、`force_delete` / `rewrite_mode` 指定時は「指定は既存ジョブに反映されない」旨を表示(通知方式は後続設計)。
- 取消が 409 `job_already_finished` の場合は成功扱いで終了済み状態を表示する。
- ★ 止まったジョブの復旧: リース切れ `failed`(`lock_released` を含む)の表示とロック解放操作を MVP に含める(PD §4.7、crawler-api-v0.4 §4.3)。リース期限内の `lock_in_use` は「取消を使う」旨を案内。
- ★ データソース削除: ソース削除ジョブ起動を MVP に含める(crawler-api-v0.4 §4.6)。`status=deleting` のソースはクロール起動・設定更新不可と表示。削除は索引済み文書も消えるため確認操作を機能要件に含める(CAPI-K-8)。
- メンテナンス中の表示: メンテナンスフラグは操作せず、立っている場合は起動時 409 `maintenance_enabled` と削除結果の失敗理由 `maintenance` を表示のみ。
- ★ 文書単位ビューの粒度: PD・SD 決定済みの上記 4 に限る。文書ブラウザ・文書単位の手動再試行は将来拡張。再試行は「原因解消 → ソース単位の再クロール」に統一。「停止中」(`extract_fail_count` 上限到達)表示は差分検知(将来拡張。SD §3.7)依存のため MVP では扱わない。
- ★ ダッシュボードの更新方式・履歴: 現在値のみ(履歴・推移・アラートなし)。更新は手動更新+表示中の定期更新(間隔は後続設計)。ステータス区分は 正常 / 異常 / 未設定(任意コンテナ)程度。
- MVP / 将来拡張の判断基準: PD v0.19 決定済み・§8.2 受け入れ基準にあるものと要件の候補 4 項目は MVP。それ以外の新規機能は機能ごとに明示し、既定は将来拡張(CLAUDE.md「要件にない機能を追加しない」)。
- OpenSearch 最小ビューは読み取り専用(インデックス削除・シャード再配置など操作系は含めない)。
- 書き方: 画面・API・技術の詳細は書かない。各機能に出典(PD / SD / Crawler API の章)と MVP / 将来拡張の区分を付ける。
