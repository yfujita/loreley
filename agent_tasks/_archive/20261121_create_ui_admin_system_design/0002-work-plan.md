## 11. ユーザーへの確認依頼(プラン承認時に回答をお願いします)

0001 の「★ユーザー未確認の前提」4点。承認と合わせて、それぞれ「このとおり」または「変更」を確認する。変更がなければ、文書は推奨案で書き、区分を「ユーザー確認済み」にする。

1. **止まったジョブの復旧(ロック解放)を MVP に含める**。リース切れ `failed`(`lock_released` を含む)の表示とロック解放操作を含める。リース期限内の `lock_in_use` は「取消を使う」旨を案内する(PD §4.7、crawler-api-v0.4 §4.3)。
2. **データソース削除(ソース削除ジョブ起動)を MVP に含める**。`status=deleting` のソースは、クロール起動と設定更新を不可と表示し、削除は索引済み文書も消えるため、確認操作を機能要件に含める(crawler-api-v0.4 §4.6、CAPI-K-8)。
3. **文書単位の確認ビューは PD・SD 決定済みの範囲に限る**。スキップ文書、抽出失敗、原本サイズ超過の確認のみ。文書ブラウザと文書単位の手動再試行は将来拡張。再試行は「原因解消 → ソース単位の再クロール」に統一。「停止中」表示は差分検知(将来拡張)依存のため MVP では扱わない。
4. **ダッシュボードは現在値のみ**(履歴・推移・アラートなし)。更新は手動更新+表示中の定期更新(間隔は後続設計)。ステータス区分は 正常 / 異常 / 未設定(任意コンテナ)程度。
