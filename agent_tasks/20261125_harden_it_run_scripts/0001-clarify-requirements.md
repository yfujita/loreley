## 目的

- Crawler・Indexer・api の IT 実行スクリプト 3 本の安全性を、api IT(PR #19 の対応後)の水準に揃える。
- 3 本が同時に動かないよう、確実に排他する。
- 重複している処理を共通の関数ファイルにまとめ、今後の安全性修正を 1 か所で済むようにする。

## ユーザーの回答(確定)

- Q1: Indexer IT に残骸の確認を**追加する**。コンテナの残り(`docker ps -a` が失敗したら中止)とボリュームの残りを確認し、ポート使用中の相手の表示も揃える。`data/` は無いので確認しない。
  - 経緯: 0000 の As-Is は「`docker ps -a` 失敗の扱い」と書くが、実際の Indexer スクリプトには残骸の事前確認自体が無かった(修正ではなく追加)。
- Q2: 共通の関数ファイルを `scripts/lib/` に作り、3 本から `source` する。
  - 共通にする: ログ出力(error/info)、排他ロック、前提ツールの確認、残骸の確認、ポートの確認(相手の表示を含む)、`probe_service`・`wait_for_stack`、`print_diagnostics`、`cleanup`
  - 各スクリプトの変数で渡す: ポート、固定する環境変数、起動するサービスと待つ条件、compose の上書きファイル、`data/` の有無、pytest のコマンドと既定の引数、Indexer の `LORELEY_IT_PYTEST_CMD`(指定時は uv の確認を省く)
- Q3: 通常終了と INT/TERM ではロックを必ず解除する。SIGKILL 等で残ったロックは**自動では消さない**。中止し、保持者の PID・開始時刻・スクリプト名を表示して、`rm -rf <ロック>` の手順を案内する(保持者が終了していても自動では消さない)。

## 要件

1. Crawler・Indexer に、テストが読む `LORELEY_IT_*_URL` を固定ポートの 127.0.0.1 に固定して export する(Crawler: OPENSEARCH・INDEXER・CRAWLER、Indexer: OPENSEARCH・INDEXER)。pytest を直接実行するときだけ上書きできる。
2. 事前確認は安全側に倒し、3 本で揃える。
   - `docker ps -a` と `docker volume ls` の失敗で中止する。
   - `data/` がある IT(Crawler・api)は、存在確認と一覧取得を分け、一覧を取れなければ中止する。
   - Indexer にコンテナ・ボリュームの残骸確認を追加する(Q1)。
3. テスト成功後に後始末へ失敗したら、終了コード 11(`EXIT_CLEANUP_FAILED`)を返す。テスト失敗時は pytest の終了コードを優先する。Indexer の対象は `down -v` の失敗のみ。`down` 失敗時は `data/` を削除しない(api と同じ)。
4. 排他ロック
   - 方式: `mkdir` の原子性。`flock` に依存せず macOS・Linux で動く。
   - 置き場所: `${TMPDIR:-/tmp}/loreley-it.lock`(リポジトリの外)
   - 中身: 保持者の PID・開始時刻・スクリプト名
   - 取得: 引数解析と環境変数の検証の後、事前確認の直前。`--help`・引数エラーでは取らない。
   - 取れなかったとき: 何も消さず、終了コード 1 で中止。保持者の情報と手順を表示。新しい終了コードは作らない。
   - 解除: 自分が取ったロックだけを解除する(取得に失敗した側は相手のロックを消さない)。`--keep` でもスクリプト終了時に解除する(残したスタックは次の実行の残骸確認が検出する)。
   - 残ったロック: Q3 のとおり。
5. 共通化する(Q2)。usage の表示(各スクリプトのヘッダコメントを読む方式)と `info` の接頭辞はスクリプトごとに残す。
6. 3 本で固定している環境変数の差(Crawler の `LORELEY_CRON_TIMEZONE=UTC`、api の `Asia/Tokyo`、api だけの `LORELEY_IT_ALLOW_COMPOSE_CONTROL=1` など)は今のまま残す。
7. README を更新する: 終了コード 11、接続先 URL の固定、事前確認で中止する条件(Indexer は追加分)、「同時に実行できない」をロックで拒否する内容へ、ロックの置き場所と手動解除の手順。

## 制約・前提

- 他プロジェクトのコンテナ(`opensearch-opensearch-1` など)やユーザーのデータに触れない。
- ポート 9200・8000・8001・8080 は固定のまま。
- macOS の `TMPDIR` はユーザーごとに分かれるため、別ユーザーとの排他は考慮しない(MVP)。
- 実行時は `caffeinate -i` を付ける。
- 共通ファイルは、スクリプトの位置を基準にした絶対パスで `source` する。見つからない・読めないときは終了コード 1 で中止する。

## 完了条件と検証方法

1. 3 本で URL 固定・事前確認の失敗処理・後始末失敗の終了コードの方針が同じ。0014 の検証と同じ方法で Crawler・Indexer を確認する。
   - 偽の `docker`(PATH の先頭)で `docker ps` を失敗させ、終了コード 1・何も消さないこと
   - 偽の `docker` で `compose down` を失敗させ、成功する `-k` の絞り込みで終了コード 11 になること
   - Crawler で `data/` を `chmod 000` にして中止すること
   - `LORELEY_IT_*_URL` に別の値を入れても上書きされて成功すること
   - Indexer で、残したコンテナまたはボリュームを検出して中止すること
2. 同時実行の拒否: 1 本目がロックを取って起動待機中に 2 本目(別の IT と同じ IT の両方)を起動し、2 本目が終了コード 1・保持者の情報を表示して中止すること。1 本目が成功し、2 本目がコンテナ・ボリューム・`data/` に触れていないこと。
3. 残ったロック: `kill -9` でロックを残し、次の実行が保持者の情報と手動解除の手順を表示して終了コード 1 で中止すること。手動で消せば実行できること。INT・TERM・`--keep` の後にロックが残らないこと。`--help`・引数エラーでロックを作らないこと。
4. Crawler IT 14 件・Indexer IT 40 件・api IT 23 件が、修正後に終了コード 0 で成功し、実行後にコンテナ・ボリューム・`data/`・ロックの残骸がない。
5. shellcheck が使えれば実行する。使えなければ未実施と明記し、`bash -n` を実行する(現在のホストでは shellcheck が見つからない)。
6. README と結果文書が更新されている。
