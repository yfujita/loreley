# 0040 PR #10 レビュー指摘: EP-11 の `existence` の取得方式の食い違い

日付: 2026-11-23
起点: ユーザーが貼り付けたレビュー指摘([P3])。「確認して指摘が適切であれば対応して」という指示

## 指摘

B 6.1 は、`mget` が文書単位で失敗した場合にその行だけ `unavailable.existence` を付けると記載している。一方 C 3.3 R-11 は 1 回の `ids` クエリによる検索で、検索応答から特定の文書だけの失敗を識別する設計になっていない。C に合わせて B から `mget` の文書単位の失敗の記述を削除するのがよい。

## 妥当性の確認(メイン)

- C 3.3 R-11 と 5.6 は「R-11 は 1 回の一括検索(`ids` クエリ。最大 100 件)なので、失敗(部分的な失敗を含む)はページの全行の `unavailable.existence` になる。行ごとに成否が分かれることはない」と書く(AAPI-P-42 の整理)。C 5.8 の帰属表も「R-11(EP-11)=1 回の一括検索 → 全行の `existence`」。
- 一方、B 6.1(815 行)に「`mget` が文書単位で失敗を返したときは、その文書の行だけを `unknown` にし、その行の `unavailable` にキーを付ける」が残っていた。指摘のとおり、C と食い違う(0038 の B 修正で、R-11 を一括検索として全行に付ける規則へ直した際の削り残し)。
- 同じ誤りが E 5.7(348 行)・F 5.5(489 行)にも「一括検索の全体の失敗は全行、文書単位の失敗はその行だけ」として残っていた。B 2.2(162 行)の「ロック文書の `mget` の文書単位」は EP-02・09・01 の `stalled` の読み取りを指すもので正しい(`existence` ではない)。

## 対応

- B 6.1: 該当文を「一括検索は 1 回の `ids` クエリなので、行ごとに成否が分かれることはない(C 3.3 R-11)。`document_id` が読めない行は `unknown` にする。」に置き換えた
- E 5.7・F 5.5: 「一括検索の全体の失敗は全行、文書単位の失敗はその行だけ」を「一括検索(1 回の `ids` クエリ)の失敗は全行。行ごとに成否が分かれることはない」に修正した
- 規則・ID・区分の変更なし(AAPI-P-42 の整理どおり。記述の整合のみ)。C・D は変更不要(C は元から全行、D に該当記述なし)
- 確認: `文書単位の失敗はその行だけ`・`mget` が文書単位で失敗を返した の残存は 0 件(grep)。D に `existence` と `mget` を結びつける記述なし
