# 0011 外部レビューの評価と v0.2 作成プラン

- 日付: 2026-11-13
- 契機: ユーザー指示「Crawlerの設計書をレビューしてもらった。確認して指摘が適切であれば改善した新版を作成して」(外部レビューの貼り付け。P1 が 4 件、P2 が 3 件、構成の所感 2 件)。この指示を v0.2 作成の承認として扱う(新版ファイルを作る運用は 0001・0010 のとおり)
- 方針: 各指摘を設計書の該当箇所と突き合わせて妥当性を判定し、妥当なものだけ反映する。ユーザーが未確定の判断を、ライターが確定扱いにしない。Indexer 設計・PD・SD は変更しない

## 指摘の評価と対応

| # | 指摘 | 判定 | 対応(v0.2) |
| --- | --- | --- | --- |
| ① | `connector_config` が設定スナップショット(手順 6)と別の時点(手順 8)で確定し、間の更新が混在しうる | 妥当。v0.1 は「許容する(案)」(architecture 3.2・4.5、crawler-api 4.4.1)としていたが、読み取りを 1 回にする修正は小さく、削除条件と取得対象のずれを防げる | 手順 6 で `loreley-sources` を 1 度だけ読み、`ttl` 等と `connector_config` を同じ版で確定する。`connector_config` はメモリ上の実行コンテキストだけに保持し(ジョブ記録には保存しない。Crawler 再起動時のジョブは `failed` で、再実行時に読み直すため)、診断用に読んだ設定の `updated_at` を `settings_snapshot` に記録する(案)。手順 8 は保持した値を使う |
| ② | 共有マウントが外れて 0 件になると、小さなソースは割合ルールで守られず削除されうる | 一部妥当。v0.1 の FS 3.4 が MVP の制約として既に記録している。指摘の「前回 1 件以上・今回 0 件なら保留」は PD 5.2(0 件は異常としない)と食い違うため、採否はユーザー判断 | 観測性を追加(案): 今回の列挙が 0 件で前回の登録結果が 1 件以上のとき、ジョブ記録の `warnings` に残す。運用の確認手順を FS 3.4 に書く。「保留」の挙動は新規の未決 CA-U-19 として選択肢つきで記録(確定扱いにしない) |
| ③ | 索引・マッピングの作成担当が未確定 | 妥当で、ユーザーが 0010 で確定済み | 確定として反映(`opensearch-init` が `loreley-sources` と `loreley-jobs` を作成・管理)。CA-U-11・CM-U-7・I-6 を解消に |
| ④ | 一覧・一括削除のページング・整合性の契約が不足 | 妥当。Repository の「一覧」は並べ替え・件数上限だけで、OpenSearch の既定上限(10,000 件)を超える走査の契約がない | Repository に全件走査の契約を追加(案): PIT + `search_after`、一意なタイブレーク、バルク削除、走査前の refresh。ソース削除の順 3 は条件指定の削除(案)。10,001 件以上の統合テストを 12章に追加 |
| ⑤ | 「設定削除」と「ソース削除」が同一操作 | 妥当で、ユーザーが 0010 で確定済み | 確定として反映(設定の削除=索引済み文書も削除する操作)。CAPI-U-1 を解消に |
| ⑥ | `invalid_external_id` が削除安全性に与える影響 | 一部妥当。識別子が不正な文書は `document_id` を持てず、定常状態では索引にも存在しないので、削除判定の対象外で問題ない。ただし識別子規則や Connector が変わって、以前は有効だった文書が不正になる場合は、期限削除の対象になる(小さなソースでは割合ルールで守られない) | 安全な条件と残るリスクを 7.7 に明記。テスト観点を追加。「1 件でもあれば削除を抑止する」は PD・Indexer の仕様にない新規の挙動のため、CA-U-7 に選択肢として追記(確定扱いにしない) |
| ⑦ | Crawler と Indexer の制限値の不整合 | 妥当。Indexer の上限は API で取得できず、設定ミスで本番ジョブが途中失敗する | Crawler の起動時に、Indexer と同じ名前の環境変数(compose で共通化)と自分の値を突き合わせ、超過なら起動を失敗させる(案)。上限を超えない/超えるときの統合テストを追加。Indexer に上限取得 API を追加する案は Indexer の変更を伴うため選択肢として記録するだけ |
| 構成 | 「確定」「案」「未決」が多く、実装エージェントがどこまで自律的に決めてよいか分かりにくい | 妥当 | 短い `crawler-design-decisions-v0.1.md` を追加(採用方針、ユーザー確定事項、実装着手を妨げる未決、実装時に実装者が決めてよい事項)。詳細設計書は維持 |
| 構成 | `include_patterns` は「追加」で、一般の glob の直感と違う | 既に 2.1 に明記。置き換えか追加かはユーザー未確定(CFS-U-1) | CFS-U-1 に、名称変更(例: `additional_include_patterns`)の選択肢と、設定画面での注意を追記。確定扱いにしない。decisions に Admin View 実装時の注意として載せる |

## 工程(プラン)

2. W1: architecture v0.2(正本。①②③④⑤⑥⑦)
