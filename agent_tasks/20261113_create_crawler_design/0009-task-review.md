### 3. ユーザー判断事項の統合一覧(優先度順)

設計書はすべて v0.1(ユーザー未承認)で、案・未決はユーザーの確認待ちである。各項目は設計書内で案・未決・I-n として記録済みで、確定扱いにはなっていない。

**第1群: ユーザーが確定した要件(Q1)との乖離。最優先で確認**
- **Q1「データソース設定の登録・更新・削除」の解釈(CAPI-P-11 / CAPI-U-1)**: Q1 でユーザーは「データソース設定の登録・更新・削除」を crawler-api の対象に選んだ。設計は、設定だけを消す API を置かず、設定の削除=ソース削除ジョブの起動(手順5で設定を削除)に対応づけた。理由: 設定だけを先に消すと文書・削除記録が残り、K29 の削除順序(設定の削除は最後)に反する。この解釈でよいか、別の解釈(設定だけを消す API が必要=K29 の順序の見直し)かを確認する。推奨: 案どおり。

**第2群: 実装前に判断が必要**
- **索引・マッピングの作成担当(CM-U-7 / CA-U-11 / I-6)**: 実装着手の前提。現行 `loreley-jobs` のマッピングは4項目だけの `dynamic: false` で、`loreley-sources` の索引は作成物がない。マッピング案は architecture 3.1(CA-P-49)に表で追記済み。推奨: 既存の `opensearch-init`(`infra/opensearch/schema/`)に `loreley-sources` を追加し `loreley-jobs` を拡張(Indexer が読む4項目の型は維持。Indexer の結合テストも同じ `jobs.json` を使うため同時更新)。代替: Crawler が起動時に作成。
- `source_id` の文字種(CAPI-U-4 / CA-U-15。案: 半角英数字で始まり、半角英数字・`.`・`_`・`-` のみ)。後から狭めると互換性問題になる。
- glob 構文の確定と `include_patterns` の意味=既定拡張子への追加か置き換えか(CFS-U-1)。
- `external_id` 衝突時のジョブ `failed`(CA-U-6 / CFS-U-5)。案: `failed`(1組の衝突でそのソースのクロールと期限削除が止まり続ける。`failure_detail` に後に検出された1件と `document_id` を載せ、管理者が `exclude_patterns` で除ける)。推奨: MVP は案を承認し、実運用で緩和を検討。
- 「削除中」の置き場所(CA-U-2。案: `loreley-sources.status=deleting`)。
- 連続スキップの取得段階への拡張(CA-U-16。api 3.5・SD 3.1 にない本設計の独自拡張。取得段階と登録段階の別カウンタ)。
- ソース削除中のメンテナンス確認(CA-U-17。案: 順1・2・4の送信前にフラグを確認し、立っていれば `failed`(`maintenance`)。Indexer 11章の開始前チェックリストに `source_delete` が含まれない点の確認)。
- 設定項目の必須・更新の全置換(`ttl` 等を必須・既定値なし。CAPI-U-3)、`connector_type` の変更不可(CAPI-U-8)、メンテナンス中の応答を 409 にする(503 にしない。CAPI-U-1)。
- 識別子エラー文書を `partially_succeeded` とする扱い(CA-U-7)、サイズ超過のジョブ status 影響(別記録・影響なし。CA-U-4)。
- `follow_symlinks`・`include_hidden` の初期値(両方 false。CFS-U-2)、`title` を内容から取るか(案: ファイル名のみ。CFS-U-3)。

**第3群: 実装時でよい**
- メンテナンスフラグの書き込み手段(CA-U-3。案: 運用者の手動手順。運用手順の文書化が必要)、周期形式(CA-U-8。案: 間隔(秒))、`/healthz`(CM-U-5)、SIGTERM 時の扱い(CM-U-4)、`document_id` テストベクタの置き場(CM-U-3。Indexer 側にも置くかは Indexer の変更を伴う)、Crawler と Indexer の上限整合(CA-U-14)、実機確認(CA-U-18。OpenSearch の `create`・`if_seq_no`、ロック文書の相互読み取り)、数値の実測(CA-U-1、CFS-U-6、CM-U-6)、ほか(CA-U-5・7・13、CAPI-U-5・6・8・10、CA-U-12/CAPI-U-2=Admin API 設計時)。

**第4群: Web 詳細設計の前**
- I-40(CI-U-11): 列挙中の一時失敗が列挙全体の失敗になる。選択肢 (a) Connector 内の上限付きリトライ (b) EnumerationStream の再開契約 (c) architecture 6.2 の方針変更 (d) 現状維持。MVP(FS)には影響しない。
- I-44: Indexer の文字コード対応が UTF-8・CP932 のみ(EUC-JP などは文字化けしうる)。Indexer 側の判断。FS にも当てはまる。

**既存設計との不整合(記録済み。Indexer・PD・SD は変更していない)**
