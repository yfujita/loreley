2. **要約の生成前のメンテナンスフラグ確認**: コード・README は LLM 呼び出し前と書き込み前の2回確認(0008 A1 の修正)。設計書・0014・0002 #11 は「書き込み前」のみ。承認記録は個別にはない(0020 §6 の「P2 細目」にも項目なし)。module は「書き込み前に確認」のままで、コードはその上位集合 → **方針: arch 7章・11章に「生成前にも確認する(実装で採用中。承認の個別記録なし・安全側の追加)」と注記し、module も揃える**(Phase 3b)。確定扱いにしない
3. **K 番号のない確定項目**(A3 の連続20件の打ち切りは Crawler 領域、C10 の受理まわりの細目、C1・C2・C3・C5・C9、U-6 の保持件数超過分の削除方法): arch は本文に「ユーザー承認 2026-11-12(0021 §1/§2)」と注記し、api も同様の書き方。K を新設せず注記で扱う方針で整合しているか、Phase 3c で確認する
