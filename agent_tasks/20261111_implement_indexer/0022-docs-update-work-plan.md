## 5. 区分の扱いと ID の割当

### 5.1 区分
SD の区分は「確定/案/未決/推測/導出」(arch 冒頭の凡例、api の「提案」、module の「記述あり」「導出(案)」)。方針(推奨。Q1):
- **ユーザーが明示的に承認したもの**(0002 §3 の22項目、0014、0021)は、区分を「確定」にする。根拠欄に「実装で採用。ユーザー承認 2026-11-11(0002 §3)」または「同 2026-11-12(0014 / 0021)」と書く。新しい区分は作らない
- **Crawler・infra・Admin API の設計に依存する名称・形式**(D の表)は案のまま。「Indexer 実装で採用中。Crawler 設計の確定時に再確認」と注記し、17章に「Crawler との突き合わせ」の未決を1行置く
- **実装が設計書の案どおりに実装しただけで、個別の承認がないもの**(module の M-1〜M-15 の多くなど)は区分を変えない。0001 Q2「設計書の案は実装仕様として採用する」は作業方針であり項目ごとの確定ではない(「未回答の判断は承認扱いにしない」)。module 7章には「実装状況」の注記だけを置く
- 数値は未決のまま(K39)
- 17.1・api 6章・module 7章の根拠欄に「ユーザー承認の日付(0021)」を書く。確定の説明文に承認の経緯を2文以内で添える
